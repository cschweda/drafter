# Novel Implementation Plan (v0.26.0)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Novel as a first-class choice: a plain Markdown file with chapters and sections that a novelist can outline, reorder, focus on, count, give targets, and track with a synopsis and a status.

**Architecture:**
- A new framework-free package, `@drafter/novel`, reads a Markdown text's structure and works out moves. It does this by a linear line scan that skips fenced code and the metadata comment, not by the full mdast parse, so it is cheap on every keystroke.
- It also reads and writes the kept facts in the existing trailing `<!-- drafter {…} -->` comment (`@drafter/markdown`'s meta helpers).
- The web app adds:
  - a Novel document type, a Markdown document whose meta says `"template": "novel"`;
  - Novel views of the Outline and Cards tabs, beside the script views;
  - focus on one passage, using CodeMirror folding;
  - per-passage counts and targets.

**Tech Stack:** TypeScript, pnpm workspace, Vitest and fast-check, Nuxt 4 / Vue 3.5 / Nuxt UI 4, CodeMirror 6, Playwright (five projects), Biome.

**Spec:** `docs/drafter-novel-design.md` (approved 2026-11-03). Goals 1–7 only; goal 8, the manuscript exports, is v0.26.1 and gets its own plan.

## Global Constraints

- **The file stays plain Markdown.** The only thing Drafter adds is the existing trailing `<!-- drafter {json} -->` comment, written with `setMarkdownMeta` and read with `readMarkdownMeta` and `findMarkdownMeta` (`packages/markdown/src/meta.ts`).
- **The structure:**
  - A chapter is a `#` heading. A section is a `##` heading, or a thematic break (`***`, `* * *`, `---`, `___`) that starts an untitled section.
  - A `#` heading whose text begins with `Part` (case-insensitive, followed by a space or the end) is a part. It groups the chapters after it, up to the next part.
  - `###` and deeper are text, not structure.
- **Statuses:** exactly `To do`, `Draft`, `Revised`, `Done`, stored as `todo`, `draft`, `revised`, `done`.
- **Words** are counted as `wordsIn` (`packages/markdown/src/words.ts`) counts them, so totals agree with the status bar.
- **A move** is one text change in one undo step; the moved text is unchanged byte for byte.
- **Focus** never removes text from the document. A save, a draft, a snapshot, and every export always write the whole book.
- **Performance:** typing in a 120,000-word novel must make no long task (the budget in `apps/web/e2e/show-changes.spec.ts`'s long-task check).
- **No novel view says** "scene heading", "INT.", or "page(s)".
- **Clean room:** the sample novel and every fixture are original. No other app's code, templates, or text.
- **Process:**
  - Every package `src` change has a Vitest test, and every UI change a Playwright test in all five projects.
  - Browser tests whose names include "long task", "quickly", "budget", or "within" are skipped on CI.
  - The CHANGELOG is updated with each task's commit.

## Review Focus

1. **A heading inside fenced code, or a `#` in the metadata comment, isn't structure.** Test in Task 1: ```` ```\n# not a chapter\n``` ```` gives no chapter.
2. **A setext heading (`Title\n=====`) is a chapter, and `----` under text is a section heading, not a scene break.** Test in Task 1.
3. **Moving the last chapter of a part, or a section across chapters, keeps every byte, and the meta comment stays last.** Property test in Task 2: after any legal move, the multiset of lines equals the original and the meta comment stays at the end.
4. **Hostile or broken kept facts** (a non-object, `__proto__` keys, a 10 MB synopsis, an unknown status) are ignored or capped, never thrown. Test in Task 3.
5. **Focus survives an edit that removes the focused heading:** focus ends and the whole book shows, with no error. Browser test in Task 7.

### Task 1: `@drafter/novel`: the structure of a novel

**Files:**
- Create: `packages/novel/{package.json,tsconfig.json,tsdown.config.ts,README.md}`, modelled on `packages/story-map`.
- Create: `packages/novel/src/structure.ts`, `src/index.ts`.
- Test: `packages/novel/test/structure.test.ts`, `test/structure.properties.test.ts`, `test/scaling.test.ts`.

**Interfaces:**
- Produces:
  - `export type NovelKind = 'part' | 'chapter' | 'section'`
  - `export interface NovelNode { id: string; kind: NovelKind; title: string; heading: { from: number; to: number }; span: { from: number; to: number }; words: number; ownWords: number; children: NovelNode[] }`
    - `id` is `${kind}:${slug(title)}:${ordinalAmongSameKeyedSiblings}`.
    - An untitled scene-break section is titled `''`, with `id` `section::${n}`.
    - `span` runs from the heading's start to the next sibling-or-ancestor's heading, or the text's end, but never into the metadata comment.
  - `export interface NovelTree { preamble: { from: number; to: number } | null; parts: boolean; nodes: NovelNode[]; words: number }`
    - `nodes` holds parts when there are any, else chapters.
  - `export function novelStructure(text: string): NovelTree`, one linear pass.
  - `export function nodeAt(tree: NovelTree, offset: number): NovelNode | null`, the deepest node containing `offset`.
  - `export function findNode(tree: NovelTree, id: string): NovelNode | null`

- [ ] **Step 1: Write the failing tests**, in `test/structure.test.ts`:
  - `reads chapters and sections, with their words`: `'# One\n\nA b c.\n\n## Arrival\n\nD e.\n\n# Two\n\nF.\n'` gives two chapters. The first has `ownWords` 3, one section with `words` 2, and `words` 5.
  - `reads a part`: `'# Part One\n\n# The Lighthouse\n\nText.\n'` gives `parts: true` and one part with one chapter.
  - `starts an untitled section at a scene break`: `'# One\n\nA.\n\n***\n\nB.\n'` gives chapter One with one section, `title ''`.
  - The Review Focus 1 and 2 tests, as written there.
  - `stops before the metadata comment`: the last node's `span.to` equals `findMarkdownMeta(text).from`.
  - `keeps text before the first heading as the preamble`.
- [ ] **Step 2:** Run `pnpm --filter @drafter/novel test`. Expected: FAIL (the module is missing).
- [ ] **Step 3: Implement `novelStructure`** as one linear line scan that tracks the open fence (```` ``` ```` or `~~~`). For the setext and thematic-break rules follow CommonMark: a `---` line directly under a non-blank paragraph line is a setext `##`, and otherwise it is a break.
- [ ] **Step 4: Property and scaling tests:**
  - For random documents built from heading, paragraph, and break lines, the spans of the top-level nodes plus the preamble tile the text up to the meta comment with no gap or overlap.
  - `novelStructure` on 120,000 words is under 50 ms, and at 4× the size is under 8× the time (`scaling` as in `packages/markdown/test/scaling.ts`).

- Produces:
  - `export type NovelTarget = { before: string } | { after: string } | { into: string }`
    - `into` makes the node the first child of a part or chapter, for a chapter or section dragged onto another.

### Task 3: Kept facts: status, synopsis, and targets

**Files:**
- Create: `packages/novel/src/facts.ts`.
- Test: `packages/novel/test/facts.test.ts`.

**Interfaces:**
- Consumes: `readMarkdownMeta`, `setMarkdownMeta` (`@drafter/markdown`); `NovelTree` (Task 1).
- Produces:
  - `export const STATUSES = ['todo', 'draft', 'revised', 'done'] as const; export type Status = (typeof STATUSES)[number]`
  - `export const STATUS_LABELS: Record<Status, string>`, with exactly `To do`, `Draft`, `Revised`, `Done`.
  - `export interface Facts { status?: Status; synopsis?: string; target?: number }`
  - `export interface NovelFacts { bookTarget?: number; nodes: Record<string, Facts> }`, with `nodes` made by `Object.create(null)`.
  - `export function readFacts(text: string): NovelFacts`. Limits: a synopsis at most 2,000 characters, cut; a target an integer from 1 to 10,000,000, else dropped; unknown statuses dropped; non-objects ignored; never throws.
  - `export function writeFacts(text: string, facts: NovelFacts): string`. It keeps every other meta key (`template`, the draft facts) and writes `novel: { bookTarget, nodes }` under the meta.
  - `export function renameFacts(facts: NovelFacts, before: NovelTree, after: NovelTree): NovelFacts`. When one heading's text changed between two trees of the same shape, it moves that node's facts to the new id.
  - `export function orphanedFacts(facts: NovelFacts, tree: NovelTree): string[]`: the ids with facts but no node.

  - A round trip.
  - The Review Focus 4 test (each hostile input, by name).
  - `writeFacts` keeps the draft meta keys.
  - `renameFacts` follows a rename.
  - `orphanedFacts` lists a heading renamed outside the app.

**Files:**

**Interfaces:**
- Consumes: Tasks 1–3, and `useEditor()` (view, kind).
- Produces:
  - `export function useNovel(): { tree: Readonly<Ref<NovelTree | null>>; facts: Readonly<Ref<NovelFacts>>; setFacts(id: string, facts: Facts): void; move(id: string, target: NovelTarget): boolean; goto(id: string): void }`
  - Its tree is recomputed on doc changes, coalesced to one per animation frame.
  - `setFacts` dispatches one transaction that rewrites the meta comment, annotated as an app change.
  - Renames carry facts in the same transaction, through an `EditorState.transactionExtender` that runs `renameFacts`.

Each row shows:
- the title (or "Scene break" for an untitled section);
- the word count;
- the target progress, when a target is set;
- the status, as a small menu;
- the synopsis, editable in place as the script Outline's synopsis is.

The keys:
- Enter goes to the passage.
- Alt+↑/↓ moves it, the same keys as scene moves (`apps/web/app/outline/move.ts` keymap).
- Rows drag to reorder, with a drop indicator.
- After a move, the moved row keeps focus.
