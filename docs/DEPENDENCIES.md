# Dependencies

Drafter takes as few dependencies as it can, and none from the screenwriting domain: no Fountain parsers, no screenplay formatters, no other screenwriting application's libraries. [Clean-room implementation](clean-room.md) explains why.

Every dependency is listed here with the reason it's needed. A new one gets an entry **before** it's added, saying why it's needed and confirming that it isn't a screenwriting tool or a Fountain library. If you're unsure whether a package counts, don't use it.

## Runtime

| Package | Depends on | Why |
|---|---|---|
| `@drafter/fountain` | nothing | The parser is self-contained. |
| `@drafter/templates` | `@drafter/fountain` | Types only (`Block`, `BlockKind`); nothing from it runs. |
| `@drafter/layout` | `@drafter/fountain`, `@drafter/templates` | Reads parsed documents and resolves roles. |
| `@drafter/render-pdf` | `@drafter/layout`, `@drafter/markdown`, `@drafter/templates`, `pdf-lib`, `@pdf-lib/fontkit` | Writing PDF files, from layouts, at the template's paper size. `pdf-lib` (1.17.1) and `@pdf-lib/fontkit` (1.1.1) are pinned exactly, not by range: the Markdown renderer pads the glyphs of fontkit's font subsets through pdf-lib's private embedder (`evenGlyphs` in `src/document/render.ts`; DECISIONS, Markdown PDF), so an upgrade must be checked against that patch and its tests first. pdf-lib can only embed the 14 standard PDF fonts without fontkit, and Drafter embeds Courier Prime. General-purpose PDF libraries, not screenwriting tools. Its tests also use `@drafter/fountain` and, to build CommonMark trees for the document renderer's tests, `mdast-util-from-markdown`, `micromark-extension-gfm-footnote`, and `mdast-util-gfm-footnote` (the versions `@drafter/markdown` pins, listed below), all as development dependencies. At runtime it takes one thing from `@drafter/markdown`, the footnote numbering walk (`footnotes`), so the PDF numbers notes with the Preview's own code, and it takes it from the parser-free subpath `@drafter/markdown/notes`: it never parses (the caller hands it the tree, over its own `DocNode` type) and loads no Markdown parser, in a bundle or in Node (`test/no-parser.test.ts` checks the built package as Node imports it). |
| `@drafter/render-text` | `@drafter/layout`, `@drafter/templates` | Writing layouts as fixed-width text, on the template's character grid. Types only (`Layout`, `LayoutLine`, `Template`); nothing from them runs. Its tests also use `@drafter/fountain`, as a development dependency. |
| `@drafter/markdown` | `mdast-util-from-markdown`, `micromark-extension-gfm-footnote`, `mdast-util-gfm-footnote` | Markdown documents, moved out of the app so the HTML export (and later the command line) reads a document exactly as the Preview does: `parseMarkdown` (CommonMark with GitHub's footnotes, the nesting guard `containerDepth` before it, `NestedTooDeeply` past `MAX_NESTING`), the footnote numbering walk `footnotes` (the one the Preview, the word count, and `@drafter/render-pdf` share), `markdownTitle` and `retitleMarkdown`, and `countWords` and `wordsIn`. A second entry, `@drafter/markdown/notes`, is the footnote walk alone, with nothing of the parser, for `@drafter/render-pdf`. Pure and DOM-free; the Preview's drawing stays in the app. The three third-party packages are the ones the app used to declare, at the same pins (described under the app, below). Workspace edges: none. Its property and timing tests use `fast-check`, which the root provides. |
| `@drafter/render-html` | `@drafter/layout`, `@drafter/templates` | Drawing laid-out pages as accessible DOM for the Script pane. Its API is written in their types (`Layout`, `Page`, `LayoutLine`, `Template`), and the role rules it reads to find speeches are the template's own; nothing from either runs. Its tests also use `@drafter/fountain`, as a development dependency. |
| `@drafter/lint` | `@drafter/fountain`, `@drafter/templates` | Reads parsed documents and the parse diagnostics they carry, and a template's `lint` settings. Its API is written in their types (`Doc`, `Span`, `TextChange`, `Template`), so both are dependencies rather than development dependencies. `manual-contd` also calls `resolveRole` from the templates, to decide which blocks print as the layout does. Its tests also use `@drafter/layout`, as a development dependency: they lay generated scripts out with `paginate` and check that `manual-contd` reports exactly the cues the layout adds a `(CONT'D)` to. |
| `@drafter/notes` | `@drafter/fountain` | Reads and writes keyed notes (`[[Head: body]]`, Phase 2 design §5.3) and holds the text helpers every structural edit shares (taking a line out, the stray-`/*` gate, line breaks). Its property tests use `fast-check`, which the root provides. |
| `@drafter/outline` | `@drafter/fountain`, `@drafter/layout`, `@drafter/notes`, `@drafter/templates` | Structure (Phase 2 design §5 and §6): the scene index, the edits that move and annotate scenes, treatments, the Structure strip's geometry, and the whole script as Markdown. It reads parsed documents, resolves roles, and reads keyed notes; from `@drafter/layout` it takes the pages a scene sits on and, for the Markdown, `sceneNumbersFor` (the scene numbers the PDF prints, from the one function `paginate` uses) and `titleKeyPrints`. Workspace edges only, nothing third-party. Its tests also use `@drafter/lint` and `@drafter/render-text`, and, to read its Markdown back with the app's own CommonMark parser, `mdast-util-from-markdown` (the version `@drafter/markdown` pins, listed below), all as development dependencies; nothing of Markdown is imported at runtime. Its property tests use `fast-check`, which the root provides. |
| `@drafter/compare` | `@drafter/fountain`, `@drafter/layout` | A line diff of two versions of a script (Myers, written for Drafter from the published algorithm; no diff library), the changes it makes, and where they fall on the newer version's laid-out pages. Types only (`Span` from the parser; `Layout` and `LayoutLine` from the layout, whose lines carry the source spans a change is matched by); nothing from either runs. Its tests also use `@drafter/templates`, as a development dependency, to lay their scripts out with the built-in templates, and `fast-check`, which the root provides. |
| `@drafter/history` | `@drafter/fountain`, `@drafter/outline`, `@drafter/templates` | Version history's scene matching (version-history design §3 and §11): a scene print of each scene version (a 53-bit hash and a bottom-k sketch of three-word shingles, both written for Drafter from their textbook descriptions; no hashing or MinHash library), which scenes of past versions are deleted now, one scene's versions, and where Put back goes. It parses a version with `@drafter/fountain`, reads its scenes with `@drafter/outline`'s scene index, and takes the template the text names from `@drafter/templates`' built-ins, so all three run. A workspace package with no third-party code. Its property tests use `fast-check`, which the root provides. |

Its development dependency is `@types/nspell` (below). |
| `@drafter/cm-fountain` | `@drafter/fountain`, `@drafter/lint`, `@drafter/templates`, `@codemirror/state`, `@codemirror/view`, `@codemirror/language`, `@codemirror/autocomplete`, `@codemirror/lint` | The editor: the parse held in the editor's state, the highlighting read from it, and the keymap, completion, folding, and lint that read it too. The CodeMirror packages are CodeMirror 6, a general-purpose editor, not a screenwriting tool, and they know nothing about Fountain. `@drafter/fountain` is the only parser, and Drafter writes no Lezer grammar. `@codemirror/state` holds the text and the parse (a state field), `@codemirror/view` draws the text and the highlighting (decorations and a view plugin), `@codemirror/language` folds ranges, `@codemirror/autocomplete` is the completion popup, and `@codemirror/lint` shows problems and their fixes. `@codemirror/language` brings the `@lezer/*` packages with it, and nothing in Drafter calls them. `@drafter/fountain`'s `Doc` is in the package's API, so it is a dependency rather than a development dependency, and `@drafter/lint` and `@drafter/templates` supply the problems and the template settings the editor shows. Its tests also use `jsdom` and `fast-check`, which the root provides. |
| `@drafter/fdx` | `@drafter/fountain`, `@drafter/templates` | A strict XML reader and writer of its own (no DOM, no XML library); `toFdx`, which maps a parsed script to Final Draft XML using the template's roles; and `fromFdx`, which maps Final Draft XML back to Fountain text and checks each block with the Fountain parser; and `fromOsf`, which reads an Open Screenplay Format document (Fade In's) with the same reader, turns it into the tree `fromFdx` reads, and maps it through the same importer. |
| `@drafter/archive` | `@drafter/fdx` | Files from other screenwriting apps that come packed as a zip (`.highland`, `.fadein`): a strict, read-only zip reader of its own, written from PKWARE's APPNOTE.TXT (no zip library: one would bring writing, zip64, encryption, and streaming from disk, all of which Drafter refuses), and the script inside each. Inflating is the platform's `DecompressionStream('deflate-raw')` (browsers, Electron's renderer, and Node 22), not a dependency; where it is missing, a deflated entry is refused. `@drafter/fdx` gives the shape every import returns (`FdxImport`, from the Highland reader on) and, from the Fade In reader on, the strict XML reader for its OSF. Its tests build their archives with `test/make-zip.ts`, which deflates with Node's built-in `zlib`, and parse an imported script with `@drafter/fountain`, a development dependency; its property tests use `fast-check`, which the root provides. |
| `@drafter/cli` | `@drafter/fountain`, `@drafter/templates`, `@drafter/layout`, `@drafter/render-pdf`, `@drafter/render-text`, `@drafter/fdx`, `@drafter/archive`, `commander` | The engine packages it drives (`fdx` and `archive` for `drafter convert`, the same importers and refusals the app's Open uses), and command-line argument parsing; commander is a general-purpose CLI library. |
