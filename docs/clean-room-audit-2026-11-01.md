The second full audit of Drafter against its [clean-room rules](clean-room.md). [Audits](AUDITS.md) lists every audit, newest first.

**Date:** 2026-11-01
**Auditor:** an AI agent (Claude), working read-only on the code. Only documentation was changed, in one commit (see "Changed with this audit").
**Overall result:** **PASS WITH FINDINGS.** No copied code, no screenwriting or Fountain dependency, no copyleft code in anything shipped, and no committed file from another app or another person's script were found. Two small items should be fixed (a film catchphrase that came back in one test, and an unrecorded source for 18 Final Draft element names), and a few more are recommended.

## 5. Similarity spot-check of the new modules: no sign of porting (a limited check)

**Method.** Read the identifiers, constants, and structure of the largest new modules: `packages/fdx/src/import.ts` (1,441 lines), `xml.ts`, `export.ts`, and `osf.ts`; `packages/archive/src/zip.ts`, `zip-write.ts`, `highland.ts`, and `fadein.ts`; `packages/history/src/cuts.ts` (911), `cuts-file.ts` (618), `draft-file.ts`, and `hash.ts`; and `packages/compare/src/myers.ts`. No other implementation's source was fetched or opened; comparisons are with the auditor's general knowledge of well-known projects. The Story map isn't built yet: `story-map` holds only its plan.

**Results.**
- **The FDX reader** is a hand-written strict XML reader (`xml.ts`: `readXml`, `NAME_START`/`NAME_CHAR` from the XML specification's productions, `MAX_XML_DEPTH`, entity and DTD refusal) feeding a tree mapper. There is no DOM, no SAX-style callback API, and nothing of the naming of common JavaScript XML libraries or of any Final Draft converter the auditor knows. Its comments cite the technical design (§6.3) and DECISIONS.
- **The zip reader** uses APPNOTE.TXT's record signatures (`0x04034b50`, `0x02014b50`, `0x06054b50`, `0x07064b50`) and flag bits (encrypted, data descriptor, strong encryption, UTF-8), which the format dictates, with Drafter's own names (`findEnd`, `listZip`, `readEntry`, `ZIP_LIMITS`). Inflating is the platform's `DecompressionStream`; there is nothing of JSZip's or fflate's structure.
- **Cuts and drafts** are built on Drafter's own diff (`@drafter/compare`'s Myers, written from the published paper) and its own scene index, with Drafter's vocabulary (`findCuts`, `sceneCuts`, `PassageFinder`, `mergeCuts`, `verifyCuts`). Nothing is a known project's structure.
- **One note: the scene hash** (`packages/history/src/hash.ts`). Its comment says it was "written for Drafter" from "mathematical constants, so they owe nothing to any library". Its shape follows two well-known public-domain techniques: the 16-13-16 xor-shift-and-multiply finaliser of MurmurHash3, and the two 32-bit `Math.imul` lanes combined into 53 bits (`(b & 0x1fffff) * 2**32 + a`) of the widely shared `cyrb53` snippet, which also uses the golden-ratio multiplier `0x9e3779b1`. The other constants differ (the fractional parts of √2 and √3, which SHA-256's initial values also use). Both techniques are public domain and not from screenwriting software, so this isn't a clean-room breach, but the comment would be more accurate if it named the techniques (Recommended).
- **What this can and cannot show.** It rules out a wholesale port, a copied table, or code shaped like the projects the auditor knows. It cannot prove that no idea was absorbed from memory, and it does not compare against code the auditor doesn't know.

## What an audit like this cannot prove

- **Independent creation is a fact about process, and a repository can only record it.** These checks find copying that leaves traces: headers, identical structure, foreign files, known sample text, and odd names. They can't detect code paraphrased from memory, or ideas absorbed from code someone read years ago.
- **AI training data.** The assistant was told not to read other implementations, and nothing reproduced was found. No one can list or remove what a model learned in training; check 6's unsourced names are an example of knowledge with no recorded source.
- **Comparison scope.** The similarity check relies on the auditor's knowledge of well-known projects, at a high level. Comparing against other screenwriting code would mean reading it, which would break the clean room. A proper similarity analysis needs an independent party who never contributes to Drafter.
- **The maintainer's outline** was checked by markers, not against its text, which this audit deliberately never opened. A line of it that matches none of the markers wouldn't be found.
- **Point in time.** This covers the commits above. The published npm tarballs, the signed desktop installers, and the GitHub Releases' files were not unpacked; the shipped-assets list comes from the source, the build, and `check-asar.mjs`.
- **Not legal advice.** Licence classifications rely on the packages' declared licence fields and the files read here.
