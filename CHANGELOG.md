# Changelog

All notable changes to Drafter are recorded here, and every push updates this file. Add entries under **[Unreleased]**, grouped as Added, Changed, Deprecated, Removed, Fixed, or Security. The pre-push hook in `.githooks/` rejects a push when none of its commits touch this file.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and packages follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html). When a release is cut, its entries move from [Unreleased] into a new section headed with the version and date, with a short summary above them.

## [Unreleased]

### Changed

- `apps/desktop`: **the Windows on Arm (arm64) installer is no longer built**, for now; it may come back later. Windows 11 on Arm PCs (a Snapdragon laptop, or Windows 11 in a VM on an Apple silicon Mac) can use the x64 installer, which Windows runs under its built-in emulation. CI drops the `windows-arm` job, so a release waits for the Linux and Windows jobs and carries five files.
- README: **badges at the top**: the latest release, the desktop build, the Netlify deploy, the licence (MIT), drafter.dev, the platforms, and Fountain.

## [0.22.0] - 2026-10-30

**Export as HTML and EPUB, and open formats said plainly.** A script or document exports as one web page that opens anywhere with no connection (dark, with a light switch; the exact pages or a reading view), or as an e-book for an e-reader or a tablet; `drafter build --html` does the same from the command line; and a new Open formats help page, with About, links to the open, public-domain specification of the `.drafter` package.

### Added

- **Export as HTML: one web page that opens anywhere, with no connection.** Export → HTML (in the Export menu, the app menu, the command palette, and the desktop app's File › Export) saves a screenplay, a stage play, or a Markdown document as one `.html` file to send to anyone: it opens in any browser, on a computer or a phone, with nothing to install and nothing loaded from the internet. A script's page opens on its **Pages**, laid out exactly as the Script tab shows them, in Courier Prime; **Reading** shows the same script as a page to read, each speech under its character's name in a color of its own, with a band of the acts and scenes along the top to jump to, and a line over the title giving the kind, the page count, and the running time at your own minutes a page. A Markdown document's page is the document as the Preview draws it, with its links and footnotes, and its words and reading time. It opens dark, with a switch to light; the reader's choices are remembered in their browser, printing gives light pages, one script page to a sheet, and with JavaScript off the page still shows everything. The export options' scene numbers and title page apply, and your notes are in Reading only if you choose Include notes. Open refuses a web page ("Drafter can’t open a web page … Open the script it was made from instead."), and the desktop app writes an `.html` only where you chose to save an export. A 120-page script's page is under 1 MB.
- **`drafter build script.fountain --html script.html`** writes the same page from the command line (scripts only, notes left out).
- **Export as EPUB, for reading a draft on an e-reader or a tablet.** Export → EPUB (in the Export menu, the app menu, the command palette, and the desktop app's File › Export) saves a screenplay, a stage play, or a Markdown document as an `.epub` e-book, which flows to the reader's screen and type size where a PDF keeps its pages. A script's e-book is its reading view: scene headings, action, and each speech under its character's name, one chapter per act (the whole script as one when it has no acts), with a contents list of the acts and their scenes; the title page's title, credit, and author open it, the export options' scene numbers and title page apply, and your notes are in only if you choose Include notes. Character names are in color where the screen has it, and always printed. A Markdown document's e-book is the document, one chapter per `#` heading, with its links and its footnotes (at the end of their chapter, linked both ways). It has no script and loads nothing from the internet; it carries Courier Prime for a script, only in the styles the script uses, and a document uses the e-reader's own type. Each script is one book to your e-reader whatever you change in it, so a new export replaces the old one on most e-readers instead of sitting beside it as a second copy. Open refuses an `.epub` ("Drafter can’t open an e-book … Open the script it was made from instead."), by its name or its contents, and the desktop app writes an `.epub` only where you chose to save an export.
- `@drafter/archive`: **a small zip writer**, `zipStored`, for the EPUB: every entry stored (not compressed), names in UTF-8, the package's own CRC-32, and a fixed date, so the same entries always make the same bytes; it refuses any name its own zip reader would refuse (`..`, a leading `/`, a drive letter, a backslash, a control or bidi character), a name too long for a zip, and two names that differ only by case. A new package, `@drafter/render-html-file`, makes both files with no browser, for the app and the CLI: `renderScriptHtml`, `renderDocumentHtml`, `renderScriptEpub`, `renderDocumentEpub`, `epubIdentifier`, `epubStylesUsed`, and `scriptAuthor`.
- **Open formats, said plainly.** A new help page, **Open formats** (Help, and the palette), says what every file Drafter writes is (Fountain, Markdown, and the small block Drafter adds at the end, in plain JSON) and links to the open specification of the `.drafter` package, which is in the public domain (CC0) so any app may read and write it. **About Drafter** links to the specification too.

### Changed

- **Include notes covers HTML and EPUB too.** The export option is now **Include notes (Markdown, HTML, and EPUB)**.

- **The Markdown parser and the scene colors live in packages**, for the HTML export. A new package, `@drafter/markdown`, holds the Markdown document's parser (with its footnotes and nesting guard), its footnote numbering, its title, and its word count, which the Preview and the PDF now share; the PDF and the Preview number footnotes with one piece of code instead of two. The scene colors' values join `@drafter/notes`. Nothing you see changes.

## [0.21.0] - 2026-10-30

**Seeing the script: Scaffold, the Stats tab, and who is in every scene.** Scaffold is a new tab that shows who is in the scene you're writing, with a page for every character and every place, the cast, and the places; Stats is now a tab, with each character's screen time, share of the dialogue, and who they are most often with; and Character by scene lays the whole script out as a grid of who is where, with long absences marked.

### Added

- `@drafter/outline`: **each scene's speeches.** The scene index now lists every speech in a scene, in order: who says it, where its cue is, and how many words it has (both sides of a dual-dialogue pair in full, a lyric's words included, and a cue with only a parenthetical as a speech of no words). What's said before the first scene or section, such as a cold open, is the index's new `opening`, with its own speeches, words, and timing; what's said between a section's heading and its first scene (a cold open under `# Act One`) is that section's, with its own speeches, words, and timing too. A speech is counted once, in the opening, a section, or a scene, in the same pass as the timing, so the views coming next (Scaffold, the Stats tab, and the character grid) all read the same numbers.
- `@drafter/cast`, a new package, works out **who is in each scene and where it is.** A character is in a scene when they speak in it, or when their name is in its action: in capitals (TOM), capitalised (Tom), or as their cue spells it (McCLANE), a possessive counting. A name that is also an ordinary word, such as Will, Hope, or The Driver, counts only in capitals, so "Will you look at that" doesn't put WILL in the scene, and a name of two words counts only whole, so ANN LEE is never also ANN. A name in dialogue, a parenthetical, a note, a synopsis, or the boneyard never counts, and someone who never has a cue isn't in the cast. A voice-over or off-screen line (`(V.O.)`, `(O.S.)`) in a scene counts as being in it and speaking, and a thousand names that start the same way (`THE GUARD`, `THE DRIVER`, …) cost no more to find than a few. From each scene heading it reads the location (INT. and EXT. of one place are one location), inside or outside, and the time of day. For each character it gives the scenes they're in, speaking or silent, their speeches and words, their share of all the dialogue, their screen time (once the pages are ready), their first and last scene, every absence of 20 pages or more, and who they share the most scenes with; and for each location, its scenes, length, times of day, and who is there. It's the engine for Scaffold, the Stats tab, and the character grid, coming next.
- **Character names and the dictionary.** To tell a name that is also an ordinary word (Will, Hope, Grace) from one that isn't, Drafter asks its spelling dictionary, the one spellcheck uses, and remembers the answer while the app is open. It asks even when spellcheck is off: the dictionary is already on your computer, nothing goes over the network, and no marks appear in your script. Until it answers, a name counts only in capitals. The cast is worked out only while a view that shows it is open, and only once you pause typing, so a long script types as smoothly as before. With spellcheck off, the dictionary loaded for the names is let go half a minute after you close the last view that needs it.
- **Stats is a tab now.** Show stats, the Counts panel's **Stats…**, and the desktop app's View › Show stats open a Stats tab beside your script, in the pane that isn't showing the Source (on a phone, it's the one pane's tab), with focus on its first heading. Like Cards and Notes, it waits under More until you choose it. Links at the top go to each section. **Overview** is everything the Stats window showed, unchanged: today, this script with its two rates (which you can still set there), the scene headings' split, and the last 30 days. **Characters** is a table of everyone who speaks, most speeches first: their speeches, the scenes they're in, the scenes they speak in, their words, their share of the dialogue (whole percents that add up to 100 when anyone speaks), their screen time in pages and in minutes at the script's page rate (once the pages are ready), and the three characters they share the most scenes with, with how many. Each name opens that character's page in Scaffold. A Markdown document has the Stats tab too, with its words, headings, and reading time.
- **Character by scene**, the Stats tab's third section: a grid with a row for each character, in the Characters table's order, and a column for each scene, headed by its number (point at one for its heading). Each cell holds how many speeches the character has in that scene, shaded darker (or, in the dark theme, brighter) for more; a dot means they're in the scene without speaking, and an empty cell means they're not in it. The names and scene numbers stay in view as the grid scrolls in its own region. When a character is away for 20 pages or more, the empty cells between are outlined, and **Long absences** under the grid lists each one, "MAVIS: absent from page 3 to page 28 (25 pages).", going to the scene they come back in. The grid is one Tab stop: the arrow keys move between cells, Home and End go along a row, Ctrl+Home and Ctrl+End go to the corners, Page Up and Page Down move ten scenes, and Enter goes to the character's first cue in that scene, or where they're silent, to the first time the action names them; the context-menu key, Shift+F10, or a right-click opens a cell's menu with Go to, Scaffold for this character, and Scaffold for this scene. A click on a name or a scene number puts focus back on the cell you were on, and the grid keeps your place on the same character and scene when the order changes or a scene is added as you write; Enter, Go to, and Long absences land on the right line even after you've typed above it. **List** shows the same as text instead, "WREN: in 3 scenes. Speaks in 1, 3. Silent in 2.", and Drafter remembers your choice on this device. A long script stays quick: only the scenes in view, and a few each side, are drawn.
- **Scaffold**, a new tab that shows who is in the scene you're writing. **Show Scaffold** (in the palette, which also finds it by "cast", "characters", "who is in this scene", or "locations", in the desktop app's View menu, and under More) opens it beside the Source, in the pane that isn't showing it (on a phone, it's the one pane's tab). It follows your cursor: a moment after the cursor settles in another scene, Scaffold shows that one, quietly, without taking focus or saying anything. At the top are the scene's number and heading, with **Go to**, which puts the cursor at the scene and scrolls the Source to it while you stay in Scaffold (on a phone, it shows the Source). Then where the scene is (and whether it's inside or outside), when, and how long: its pages, the page it starts on, and its minutes at the script's page rate, or, until the pages are ready, an estimate from the dialogue that says so. **In this scene** lists everyone in it: first those who speak, in the order they first speak, then those only named in the action, marked **Silent**. For each, their speeches, their words, their time speaking (their words at the script's speaking pace, and that as a share of the scene's estimate), and how many other scenes they're in; **First seen here** marks anyone whose first scene this is, and a line under the table names them all. **Follow the cursor**, on the tab's bar, can be turned off, and the page keeps its scene; Show Scaffold turns it on again and shows the cursor's scene, as it is each time you open Drafter. **Scaffold for this scene**, in the Outline's and the Cards' scene menus, the Structure strip's block menu, the character grid's cell menu, and the palette (for the cursor's scene), opens Scaffold on that scene and keeps it there. Before the first scene it says "The cursor is before the first scene.", and a play's scene, whose heading names no place, says that too. A Markdown document has no scenes, so it has no Scaffold.
- **A Scaffold page for each character and each location, and the Cast and Places.** In Scaffold, every name is a link to that character's page, the place in **Where** to that location's page, and "22 more" to the character's list of scenes. A **character's page** starts with a line like "In 23 of 61 scenes. First in scene 1 (page 1); last in scene 58 (page 104)." Then their screen time (in pages, and in minutes at the script's page rate), their dialogue (speeches, words, and their share of all the dialogue, the same figures as the Stats tab), their longest absence, with a link to the scene they come back in, and every absence of 20 pages or more; the ones that need the pages wait for them. Tables follow of who they share scenes with, the locations they're in, and their scenes (each heading goes to the scene in the Source), and then **Lines**: everything they say, in the script's typeface and grouped under each scene's heading (or, for what they say outside the scenes, under "Before the first scene" or "Between scenes" and the act or sequence it's in), each going to the start of its cue's line in the Source while you stay in Scaffold, even if you've typed above it since. A lead with hundreds of speeches shows the first 100, and **Show all 212 speeches** shows the rest. A **location's page** gives its scenes, pages, minutes, and how many are inside and outside, its times of day, a table of its scenes, and who appears there, with the scenes each is there and speaks in. **Cast** lists everyone, in the Stats tab's order, with their scenes, screen time, and dialogue share, and **Places** every location from A to Z, with its scenes and pages; each has a filter that ignores capitals and accents, so "elo" finds ÉLODIE, and keeps what you typed while you visit a page from the list and come Back. Open them from the **Pages** menu on Scaffold's bar (This scene, Cast, Places), from **Show the cast** and **Show the places** (in the palette and the desktop app's View menu), from the links Scaffold shows before the first scene, from a name in the Stats tab, or from **Scaffold for this character** in the character grid's menu. **Back**, on the bar, returns to the page before, and so does Alt+Left (Option+Left on a Mac) anywhere in the tab but the filter, the tab's own panel included; going back to a scene that was following the cursor follows it again. A character or place you've written out of the script while its page is open says "No longer in the script." with a Back button, and focus goes to the page's heading; a row of a page's table that leaves with focus on it leaves focus on that table's heading. A page explains, in the same words on the scene page and a character's, who counts as in a scene.

### Changed

- **Two figures for each character mean something new**, now that the Characters table reads the same count as everything else. **Words** count dialogue and lyrics, as the running-time estimate does; before, lyrics were left out. **Scenes** count every scene a character is in, speaking or silent (named in the action); the new **Speaks in** column keeps the old figure, the scenes they speak in.
- **Help says what Stats and Scaffold count.** The Help index has a Stats and Scaffold section: what each shows, that they count the same way and never change your script, and who counts as in a scene, in the same words the scene page and a character's page use (a mention in the action counts, a voice-over counts as speaking, a name counts only in capitals until the dictionary answers, and a name of two words only whole). Technical details names `@drafter/cast` and when the cast is worked out.
- `docs`: **the Phase 2 plans are renumbered again, with Drafts and Cuts and Novel added.** This release is v0.21.0, Plan E's first part. Next come Export as HTML and EPUB (v0.22.0); **Drafts and Cuts** (v0.23.0), numbered drafts and a permanent Cuts file beside each script or novel; **Novel** (v0.24.0), a choice beside Screenplay and Stage play for drafting a novel in Markdown, with chapters, sections, focus, and counts; Plan E's second part, storylines, the Structure strip's Color by, and pacing (v0.25.0); and Plans F to H (v0.26.0 to v0.28.0), the Beat Board expected to become the Workbook. The README, the Phase 2 design, the architecture's phased plan, and the seeing-the-script design and plan say so, and `docs/DEFERRED.md` lists what this release leaves for later.

### Removed

- **The Stats window**, which the Stats tab replaces with everything it showed.

### Fixed

- **Clearing a synopsis inside a speech no longer pulls a lyric into the speech.** A synopsis line with a note on it (`= [[a note]] the.`), typed between a speech and a `~` lyric, ends the speech, so the lyric prints as its own paragraph. Clearing the synopsis keeps the note on its line, but the speech reads through a line of notes, so the lyric joined it and lost the blank line above it. Clearing the synopsis there now changes nothing, as it already did where the line of notes would join action or centered text; under a speech with a blank line or the end of the script after it, the `=` and its words still go and the note stays.

## [0.20.0] - 2026-10-30

**Formats: Fountain first, every main format out.** `drafter convert` turns Final Draft, Highland, and Fade In files into Fountain, a whole folder at once; Markdown documents get footnotes, at the end of the Preview and at the foot of the PDF's pages; the welcome, the tour, the share image, and the README say Drafter is Fountain-first, for screenplays, stage plays, and novels; and a Markdown document nested hundreds of levels deep, or with a hostile heading, can no longer hold up the app.

### Added

- **Footnotes in Markdown documents.** Write `text[^1]` where a note belongs and `[^1]: The note.` on a line of its own anywhere in the document, as on GitHub; a label can be a word (`[^source]`), and a note can run to more paragraphs, each indented four spaces. Notes are numbered 1, 2, 3 in the order you first refer to them, whatever their labels, and a note you refer to twice keeps its number. In the Preview a reference is a small raised number you can click (or press) to go to its note, and the notes are listed at the end under **Notes**, each with a button back. In the PDF each note prints at the foot of the page its reference is on, under a short rule, in smaller type: if a note won't fit under its line, the line moves to the next page with it, and a note longer than the room left goes on at the foot of the next page. A note's words count toward the document's; a note nothing refers to isn't printed or counted, and a reference with no note stays as you typed it. The Source pane shows `[^1]` in a quieter color, and the sample Markdown document has a short section on footnotes.
- **Convert many files to Fountain at once, from the command line.** `drafter convert` turns Final Draft (`.fdx`), Highland (`.highland`), and Fade In (`.fadein`) files into `.fountain` files, exactly as opening each one in Drafter and saving it would. Name files or whole folders (`--recursive` goes into subfolders); each `.fountain` is written beside its file, or into the folder `--out` names. A `.fountain` that is already there is left alone unless you add `--force`, and the file you convert is never changed. Each file gets a line saying what happened (converted, and how many items came in as notes; skipped; or refused, and why), and a summary follows; it exits 1 if any file was refused. A file that isn't a script, or that the importer turns away, is refused with the app's own words, such as "Drafter can’t open a Word document"; a Final Draft file that is too big or isn't UTF-8 text gets a short reason of the command's own. Each `.fountain` is written in full before it appears, so a full disk never leaves half a file behind (on a drive with no hard links, such as FAT or exFAT, it is copied into place instead, and a copy cut off by a crash can still be short). Run it as `pnpm drafter convert …` after a build.

### Changed

- **The welcome and the tour say Drafter is Fountain-first.** The welcome calls Drafter a Fountain-first writing app, for screenplays and stage plays in Fountain and anything else, from a treatment to a novel, in Markdown. The Fountain card adds that the script goes out in the formats the industry uses, and the Export step, now **Export, and open almost anything**, lists what Drafter exports (PDF, Final Draft, Markdown, plain text) and what Open reads (Final Draft, Highland, Fade In, Markdown, plain text). The tour isn't shown again to anyone who has seen it.
- **Drafter says it is Fountain-first, and for novelists too.** The share image, the site's title and description, and the Linux package's summary now say Fountain first, for screenplays, stage plays, and novels (written as Markdown documents), with the formats a script goes out in.
- `notAScript` and `refusalMessage` (the table of files that aren't scripts), `importKindOf`, and Open's limits (`MAX_SCRIPT_BYTES`, `SNIFF_BYTES`) moved from the web app into `@drafter/archive`, so the app's Open and `drafter convert` take in and refuse the same files with the same words. `@drafter/cli` now depends on `@drafter/fdx` and `@drafter/archive`. The command line's own reasons for a file it can't read or write are clearer too, for `build` as for `convert`: "permission denied" for a file the system won't allow, and plain words for a path that isn't a folder and for a full disk.

### Fixed

- **The tour's first card can be scrolled from the keyboard.** When its text is taller than the card allows (a short window, or a longer card), the text gets a tab stop, as a scrolling region must; it has none when it fits.
- **A Markdown document nested hundreds of levels deep is shown as "nested too deeply" at once.** Only a hostile or broken file nests like that (a line of hundreds of list marks, or footnotes defined one inside another), and it froze the app for seconds while the Preview, the word count, or the PDF read it. Drafter now checks first: deeper than 48 levels, the Preview says "This document is nested too deeply to preview. Your text is safe in the Source.", the PDF export says the document is nested too deeply to lay out, and the word count counts the plain text. Real documents never come near it.
- **A Markdown document with one very long heading no longer holds up typing.** Finding the document's title (for the window and the file's name) read a heading with patterns that slowed by far more than its length: a heading of tens of thousands of spaces or brackets took seconds, on every key. It is now read in one pass, and every ordinary heading gives the same title as before; a heading of nothing but closing `#`s is empty, as Markdown has it.
- **The Preview's lists show their bullets and numbers again.** The app's base styles took list marks off everywhere, the Preview's lists too; a Markdown document's lists, and its notes, are now marked as in the PDF.
- **The desktop quit test holds every quit, not only the first.** The app's own close flow asks, finds nothing unsaved and quits again, so a one-time hook in the test could let the app close on a fast Linux runner. Test only; the app is unchanged.

## [0.19.1] - 2026-10-30

**Two rare Markdown export lines kept as written, and Stats reads every heading at once.** A `<` before a bold or italic word starting with `@`, and a centered line with no text, now export as they should; a heading with a very long run of spaces no longer slows the Stats window.

### Fixed

- **Export as Markdown keeps two rare lines as written.** A `<` just before a bold or italic word that starts with `@` could become an email link in the Markdown, losing its characters; it is now escaped. A centered line with no text came out as `><`; it now writes nothing, as the PDF prints nothing. Both were found by a long run of the export's own random tests.
- **Stats reads every scene heading at once.** A heading with a very long run of spaces before its time of day made the Stats window's day-and-night count slow, as the split it used backtracked once per space; it is now a simple scan, with the same results.

## [0.19.0] - 2026-10-30

**Imports and Markdown out.** Drafter opens Highland and Fade In files as new scripts, opens a Markdown file as a screenplay when you want, exports a screenplay or stage play as Markdown that reads well anywhere (in a chat with an AI, on GitHub, in a notes app), and says plainly what a file is when it isn't a script.

### Added

- **Open Highland and Fade In files.** Choose Open, drop the file on Drafter, or, in the desktop app, open it with Drafter from your file manager, and a `.highland` or `.fadein` comes in as a new script, as a Final Draft file does: not saved yet, so Save asks where to put a `.fountain`, and the file you opened is never changed. A Highland script comes in exactly as you wrote it; anything else the file holds, such as pictures, is named in a note at the end. A Fade In script comes in with its scenes, speeches, and title page, and a paragraph in a style Drafter has no element for comes in with a note naming it. The message says how many notes came in, Problems lists them, and History keeps the script as it came in. A file that isn't one Drafter can read, such as a text file renamed `.highland` or a Highland file renamed `.fadein`, is turned away with the reason, and nothing opens. The desktop app offers itself for both kinds under Open With, and takes neither over.
- **Open as screenplay.** A screenplay typed in a Markdown file can now come in as a script. Choose **Open as screenplay…** in the palette or the menu (in the desktop app, File › Open as Screenplay…), pick the `.md` or `.markdown` file, and it opens as a new screenplay with its text exactly as you wrote it, line endings included. It isn't saved yet, so Save asks where to put a `.fountain`, and the Markdown file is never changed. History keeps the script as it came in. Open and dropping a file still open a Markdown file as a Markdown document, and Open as screenplay opens any other file just as Open does.
- **Export a screenplay or stage play as Markdown.** Export › Markdown (.md), the palette's Export as Markdown file, and the desktop app's File › Export › Markdown file now save the whole script as a Markdown file that reads well anywhere: in a Markdown viewer, a notes app, a website, or an AI chat. It follows your Export options just as the PDF does, so scene numbers and the title page come out the way you chose, and the toast says which ones you picked ("Exported The Call.md, with every scene numbered and no title page."). Your script itself never changes. A Markdown document's Markdown export is still its own text, as before.
- **Export options: Notes in Markdown.** A third choice in Export options, **Leave out** (the default) or **Include**. With Include, a Markdown export carries each note and synopsis as a quote where it stands, so a reader or an AI sees what you were thinking; the boneyard is always left out. It's kept for each script, like the other options, and only the Markdown export reads it: a PDF, plain text, or Final Draft file never prints notes.
- **Open says what a file is when it isn't a script.** A Word document, an RTF file, a PDF, an OpenDocument or Pages document, an older Final Draft file (`.fdr`), a Celtx project, or a zip is turned away with its kind named and what to do instead, for example "Drafter can’t open a Word document (Notes.docx). Save it as plain text or Fountain in the app that made it, then open that." An RTF or PDF is caught by what's inside it even when it's named `.txt`, so it no longer opens as a page of `{\rtf1…` codes. Nothing opens and the script you have open is left alone. Any other plain text still opens as Fountain, as before. This applies to a file you open or drop, in the browser and the desktop app. A file named on the desktop app's command line was already turned away unless its name is one Drafter opens, so there it catches an RTF or PDF given a script's name.
- `@drafter/archive`, a new package, reads Highland (`fromHighland`) and Fade In (`fromFadeIn`) files. And **the list of ignored settings is capped at 50 names** (`ignoredCount` gives the total), so a file of thousands of different empty elements can't make import slow or its report as large as the file. Neither a setting's content nor an image's bytes reaches the script by any path now, even inside an element Drafter doesn't know.
- `@drafter/fdx`: **many duplicate alternates, or many styled copies of a scene title, no longer slow an import to a crawl.** Each one compared itself with the whole stored text by working it out again; the stored text is now worked out once.
- `@drafter/fdx`: **a title page of thousands of credits no longer slows import to a crawl**, and **a title-page paragraph of a million lines, or a script line of hundreds of thousands of styled runs on export, no longer crashes** with a stack overflow.
- `@drafter/fdx`: **exporting a script of many notes on their own lines no longer slows down with their square**; each note block looks only at its own stretch of the script.
- `@drafter/fdx`: **an alternate text is imported once, however many paragraphs name it.** A hostile `.fdx` could point thousands of paragraphs at one large alternate and turn a small file into a script megabytes long; each alternate now comes in at its first reference only.

### Fixed

- `apps/web`: with two panes side by side, the first line of text in each now starts at the same height, whatever each pane shows.

  - **`manual-contd`** (info): a `(CONT'D)` typed on a cue where the layout would add one itself: the template continues speeches after action, and the same speaker spoke earlier in the scene. So it says nothing on the first speech in a scene, after someone else's, on dual dialogue, or in the stage play. - `@drafter/lint`: the `similar-names` rule (info), the last of Phase 1's rules. It finds two character names one edit apart, such as `MARGERET` beside `MARGARET`, which are probably one character typed two ways, and says so: `"MARGERET" is one letter from "MARGARET", which has 12 cues. A typo?`

So `MAX` and `MAC` (too short) and `DANNY` and `DANNYS` (a prefix) are left alone. An edit is a letter changed, added, or left out, or two letters side by side swapped, counted in code points, so an emoji is one. Names that differ only in case, such as `@McCLANE` and `MCCLANE`, are one name, and their cues add up. Names that differ only in their digits, such as `GUARD 1` and `GUARD 2` or `GUARD 12` and `GUARD 2`, are numbered characters and are never reported, in any script's digits; `AGENT 47` beside `AGENT47` differs by a space, and still is.

The five CodeMirror packages it uses are general-purpose editor libraries, listed in `docs/DEPENDENCIES.md`.

It parses the text with `\n` between the lines, whatever the file used, so the parser's offsets are CodeMirror's positions, even when an app sets `EditorState.lineSeparator`.

  - **Enter:** a plain line break, or two at the end of a scene heading or a transition, since a heading is always followed by a blank line. Just before the `)` of a parenthetical, the cursor first moves past it. A selection is replaced by one break, and every cursor gets its own.
  - **Tab and Shift-Tab:**
    - Tab on an empty line after a blank one starts a cue, with an `@` and cue mode. On an empty line under a cue or a speech it opens a parenthetical, `(|)`.

    - Tab does nothing, and so the browser's own Tab moves focus, wherever the table of technical design §3.3 gives it no meaning: a heading, a transition, a line of speech, a note, the title page, a selection, and so on. The editor doesn't trap the keyboard.
  - **Other keys:** `Mod-Alt-1` to `7` force a line's kind (heading, action, cue, parenthetical, transition, centered text, lyric), replacing the marker or wrapper it has and never changing case. `Mod-Shift-d` toggles `^` on the cue of the speech the cursor is in. `Mod-/` and `Mod-Shift-/` wrap the selection in a note or a boneyard, or insert an empty pair with the cursor inside. The save keys are the app's.
  - **Input filters:** `fountainInput()` upper-cases what is typed in a cue started with Tab and in a scene heading after its prefix, and nowhere else. `cueMode` is on from the Tab until Enter, until the cursor leaves the line, or until the `@` is deleted. Only typing is changed, as it is typed, over whole code points, surrogate pairs included. Text already in the document, a paste, a completion, and a change the app makes keep their case.
  - **Notes and boneyards:** one typed on a scene heading or a cue line stays as typed (`INT. HALL - DAY [[check the location`), and forcing the kind of a file's first line keeps its byte-order mark.
  - **Tests:**
    - Every row of the keymap table; the keys pressed in a jsdom view; and a Tab that must pass through, unprevented, wherever it has no meaning.
    - The edge cases of each command, and a scene typed from the keyboard that the parser reads as the writer meant.
    - Typing in cues and headings and nowhere else, including surrogate pairs and several cursors, and the line breaks of a CRLF file.
    - Lines of 200,000 characters, a block of 100,000 lines, a speech of 50,000 lines, and 20,000 cursors, which must be handled in under a second.
- `@drafter/cm-fountain`: autocomplete, with names, places, and titles read from the parse in the editor's state. `fountainCompletionSource` is a CodeMirror completion source, and `fountainCompletion()` is `autocompletion` with it as its only source, bringing `parsedDoc` with it.
  - **Character names:** on a cue line, which is a line under a blank one that starts with `@` or has two letters and none in lower case. The name whose last cue before the cursor is nearest comes first, then the names with the most cues. After a name and a space, or from an open `(`, it offers `(V.O.)`, `(O.S.)`, and the extensions the script uses, each on its own. A name that needs an `@` to be a cue, such as `McCLANE`, is offered only after one.
  - **Places and times:** after a scene heading's prefix and a space, the script's locations, the most used first. After ` - `, its times of day, then `DAY`, `NIGHT`, `CONTINUOUS`, `LATER`, and `MOMENTS LATER`.
  - **Transitions and sections:** on a line that starts with `>`, the script's transitions, then `CUT TO:`, `DISSOLVE TO:`, `SMASH CUT TO:`, and `FADE OUT.`. After `#`, its section titles.
  - **Where:** the parser reads a cue that is still being typed as action, so where the cursor is comes from the text of its line, by the parser's own rules, and what to offer comes from the parse.
  - **When:** the list opens when asked (Ctrl+Space), or once two characters of what is being completed are typed.
  - **Enter:** a name typed in full is not offered, so Enter goes on to the speech and does not accept a list that would change nothing. When the text typed is already one of the names, no list opens at all, even if a longer name starts with it (`DAN` beside `DANNY`): the writer types `DANN` to reach `DANNY`. Case is ignored, and every list works this way. Names are matched from their start, so `OC` doesn't offer `DOCTOR`.
  - **Tests:** what each place offers, and in what order; where a cue line can and can't be; the full name that leaves Enter alone, in the source and in a view with CodeMirror's own completion; and hostile scripts (a hundred thousand different names, places, times, transitions, sections, and extensions, and lines of a million characters) that must be answered in under a second.
- `@drafter/cm-fountain`: folding, the cursor's element, lint, and `fountain()`, which composes the whole package.
  - **Folding:** `fountainFolding()` folds a section to the next section of equal or shallower depth, and a scene to the next heading or section, from the end of the heading to the end of the last block. A folded scene shows its heading and its first synopsis; a folded section shows its title.
  - **Cursor:** `cursorElement(state)` is the block, line, and kind under the main cursor, null on a blank line, and the title page as `blockIndex` -1. `onCursorElement(callback)` calls back when that changes.
  - **Lint:** `fountainLint({ template, options })` runs `@drafter/lint` on the parse 300 ms after typing stops, with CodeMirror's gutter and tooltips, and `toCodeMirror` maps the diagnostics, a fix becoming an action. A fix applies only to the text that was linted, and inserts the editor's own line break (`\r\n` in a CRLF file). `relint(view)` lints now, with no edit, for after the template or the options change. After an edit a stale fix asks for a new lint and changes nothing.
  - **`fountain(options)`:** the parse, highlighting, input filters, keymap (at `Prec.high`), completion, and folding, and, given a `template`, lint, and given `onCursorElement`, the callback. Tab on a blank line starts a cue and opens the list of names.
  - **Completion:** a cue right under a section, synopsis, or page break is a cue line. Ctrl+Space on any other line offers the character names for the word before the cursor.
- `apps/web`: the Source pane is the editor now. It runs CodeMirror with `@drafter/cm-fountain`, so the script is colored by element, Tab and Enter work as writers expect, names and locations complete, scenes and sections fold, lint marks the gutter, and Find, undo, and redo work. The text, its undo history, and its cursor stay put when the panes swap or the window changes between one pane and two.
  - **Template:** the toolbar's chip and the status bar name the script's template, "Screenplay" or "Stage play", from its metadata block.
  - **Screen readers:** a hidden live region says the kind of element when the cursor moves to another, and nothing on a blank line. Escape then Tab leaves the editor, so the keyboard is never trapped.
  - **Unsaved edits:** until the recovery copy arrives, the browser asks before the page closes while the text differs from what the editor opened with, and the page isn't asked while they match.
  - **Spellcheck:** the browser's own, on.
  - **Packages:** the app builds the Drafter packages from their TypeScript (a Vite alias for those packages alone), so it never reads a stale `dist/`.
- `apps/web`: the Script pane shows the script's pages. A Web Worker parses and paginates the text, so typing never waits on layout, and `@drafter/render-html` draws the result.
  - **Pages:** the title page, then the numbered pages, in the theme's paper and ink. Pages that didn't change keep their elements, so typing in a long script rebuilds only the page being typed in.
  - **Clicking a line** puts the cursor at that line in the Source pane, and shows the Source pane first if it isn't on screen. **Moving the cursor** scrolls its page into view.
  - **The bar above the pages** reads "Page N of M", or "Title page", and "Updating…" while a layout is on its way; the status bar reads the same page. A blank line keeps the page of the block before it.
  - **Fit width and 100%** are a two-button toggle: Fit width, the default, scales the pages to fill the pane, and 100% is real size.
  - **Layout requests** wait for a 50 ms pause in typing and carry the whole text; a reply older than the one on screen is dropped, and a failed layout leaves the last pages up.
  - **Tests:** the request debounce, stale replies, errors, and the worker's reply; the page lookup; and in the browser, the sample's three pages, typing, clicks, following the cursor, the zoom toggle, accessibility in both themes and on a phone, and no long task while typing into a 120-page script.
  - **Packages:** the app builds the Drafter packages from their TypeScript (Vite aliases), so it never reads a stale `dist/`.
- `apps/web`: storage for projects, in `app/storage/`, with no screen yet.
  - **Database:** Dexie over IndexedDB, with technical design §8.1's whole version 1 (`projects`, `snapshots`, `templates`, `handles`, `settings`), so later plans add no migration.
  - **Projects:** create, read, update, list newest first, and remove, plus the text as last saved to its file. Updating with a new `source` re-derives the title, template, and metadata from it. Removing a project removes its saved text and file handle, never the file.
  - **Recovery-copy writer:** writes 750 ms after the last change or every 5 s of continuous typing, one write at a time, with `flush` for when the page is hidden.
  - **Files:** `decodeFile` and `encodeFile` read and write a file's UTF-8 text with its line break and byte-order mark; `titleOf` reads the title page; `fileNameFor` makes a safe name; `hashText` is SHA-256 in hex.
- `apps/web`: the Script pane after its review.
  - **A failed layout shows:** when the layout worker can't be made or fails before any page is drawn, the pane says "Couldn't lay out the pages." and the editor goes on.
  - **The pressed Fit width / 100% button** has a 1px line in the heading color under it, like the selected tab.
  - **The 120-page test** now proves the pages kept up with the typing, and that its long-task observer works.
- `apps/web`: the current script and its recovery copy, kept in the browser as you type.
  - **Opening:** the app opens the most recently updated script, or saves the screenplay sample as a script on a first visit. Opening a script gives the one editor a fresh state with its own undo history.
  - **Writing:** every change schedules the recovery-copy writer (750 ms after the last change, or every 5 s of continuous typing). The pending text is written when the page is hidden or closing, and `localStorage` holds it for a moment as well, since a closing page can start an IndexedDB write but not finish it; the next launch writes what was left.
  - **Its state:** the status bar reads "Recovery copy: kept in this browser", "may be cleared", or "unavailable", each a button that explains itself. "May be cleared" also shows a warning that can be dismissed for the visit. "Unavailable" (IndexedDB won't open, or a write fails) shows one that stays until a write succeeds, and Drafter tries again on the next change and every 30 seconds. With no IndexedDB the editor runs on the sample in memory, and text typed meanwhile becomes a script when storage comes back.
  - **The status bar's first item** reads "Sample · your edits stay in this browser", or "Not saved to a file yet"; the Source pane's bar shows the script's title.
  - **Leaving:** the interim leave warning is gone. A script that isn't a sample asks before the page closes while it has unsaved changes; a sample never asks, unless nothing can keep its edits.
  - **Projects** gain `bom`, whether the file began with a byte-order mark, for Save and Open a file to set (no new database version).
  - **Linting again:** `relint()` calls `@drafter/cm-fountain`'s `relint(view)`.
  - **Warnings:** the "may clear your recovery copy" banner doesn't flash on every launch before the storage has been checked. Both warnings sit in live regions that are always in the page, with only their contents changing: "may be cleared" in a status region, and "unavailable", which matters most, in a separate alert region, so it is announced at once.
  - **Per script:** the text a closing page leaves behind is kept per script (`drafter:unwritten:<id>`), so two tabs on two scripts can't overwrite each other's. A launch writes each one that is newer than its script's stored copy and clears the rest, and so does switching to a script from the menu: a tab that closed right after typing leaves its newest text in the stash, and the next tab to open that script shows it and writes it.
  - **Writes:** a write for a script that is no longer open fails, so the writer keeps the text, instead of reporting success. It keeps what else is recorded on the stored project (`writeSource` merges into a fresh read), so a save recorded from another tab isn't undone by the next write.
- `apps/web`: a script opens in one tab at a time.
  - **Holding:** opening a script takes the Web Lock `drafter:project:<id>` and keeps it until the script closes or the tab goes. A second tab finds it taken and opens the script read-only (no typing, no recovery writes, no stash, no leave warning), under a bar that reads "This script is open for editing in another tab".
  - **Edit here instead:** asks the other tab over the `drafter` channel. It writes its recovery copy, turns read-only, and lets go; the asking tab then reloads the script from IndexedDB and applies a leftover stash only if the stash is newer. If the other tab can't write, it keeps the script and the bar says it didn't let go.
  - **No Web Locks, or no `BroadcastChannel`:** no guard; every tab edits, as before.
  - **Switching:** switching scripts takes the new script's lock before letting go of the old one, and the editor can't be typed in during the switch, so another tab can't take the old script while this one can still edit it. A tab handing a script over lets go of the lock it was asked about, not one a switch took meanwhile, and still leaves its unwritten text for a closing page.
  - **Edit here instead is for the script shown when it was pressed:** if another script was opened while the tab waited for the lock, the lock is let go and nothing is taken over; the scripts menu doesn't switch while the handover waits.
  - **The bar is announced:** its text sits in a status region that is always in the page, and its two sentences are punctuated.
  - **Read-only editor:** a lint quick fix no longer changes the text of a read-only editor (`@drafter/cm-fountain`).
- `apps/web`: new scripts, and switching between this browser's scripts and the samples, from the toolbar's **Open** menu.
  - **The menu:** **New screenplay**, **New stage play**, this browser's scripts (most recent first, the open one marked), and **Samples**: Screenplay and Stage play. It works from the keyboard (Enter or Space opens it, Escape closes it and returns to **Open**) and closes when focus or a click leaves it.
  - **A new script** is a title page to fill in (title, credit, author, and today's date), with the cursor ready to type below it. A stage play also carries the metadata block that names its template. It has its own undo history, like every script you switch to.
  - **Untouched new scripts don't count as changed:** a new script remembers the text it started from, so leaving it before you type asks nothing, and typing it back to the template ends the changes.
  - **Samples** open as scripts of their own that stay in this browser with your edits to them. Switching keeps the script you leave first; if it can't be kept, nothing is switched.
  - **Remove from this browser** asks first and says the file isn't touched (and when the script has never been saved to a file, that removing it deletes the only copy; when it has a file but changes since its last save, that those changes are lost). Removing the open script opens the most recent other one, or the screenplay sample. A script another tab has open is never removed, and the menu says so.
  - **Another tab:** switching to a script another tab holds opens it read-only, and the script you left is let go.
  - **One switch at a time:** a double click on New screenplay makes one script, and a second switch can't load over text typed after the first. The menu's items are disabled while one is under way.
- `apps/web`: Save and Save As. **Save** (toolbar, `Mod+S`) writes the script to its file: in place on Chromium, remembered across reloads, and by download in browsers without the File System Access API. **Save As…** (Open menu, `Mod+Shift+S`) asks where. A sample saved this way becomes a script of the writer's own and the sample is left as it was. The status bar reads "Saved just now", "Saved N min ago", "Saved at 3:42 PM", or "Unsaved changes", and the tab title starts with a bullet while there are changes. Files keep their line breaks and byte-order mark. All file access goes through one `FileAccess` interface (`storage/files.ts`) that a desktop build can replace.
  - **Tied to its script:** a save is recorded against the script it started on. If the writer switched scripts while the file was being picked or written, the file still gets that script's own text (read from storage, not from the editor, which shows the other one), and the record of the file's name, handle, and saved text goes to that script, not the open one. A sample saved while another switch finishes first becomes a script of its own without being opened, and Save waits for a switch that is under way.
  - **Announced:** every save is announced to a screen reader, not only the first; opening a saved script or reloading the page announces nothing.
  - **Refused writes:** a refused write no longer hides its real error behind a failed close, the message points to Save As, and it goes away when the script changes.
- `apps/web`: open a file. Open ▸ **Open a file…** (the browser's file picker where it has one, else a file input), or drop a `.fountain` or `.txt` file anywhere on the window, and it opens as a script of its own, clean, with its line breaks and byte-order mark kept for the next save. On Chromium it keeps the file, so Save writes it back in place.
  - A file that is already open (the same file on disk) opens its script instead of a copy.
  - Where saving downloads, a file whose title matches a script in the browser asks first: **Replace that script** (one undoable change), **Open beside it**, or **Cancel**.

  - A script with no title page Title is called after its file.
  - **Dropped on the editor:** a file dropped on the script's text opens as its own script and is not also pasted into the one that was open (CodeMirror's own drop handler is turned off for files; text dragged into the editor still drops in as before). A refused file dropped there inserts nothing.
  - **Refusals are announced again:** the same message twice in a row is heard twice (it is cleared, drawn empty, and then set), as is the read-only tab's "Choose “Edit here instead” first" and a failed save.

### Changed

- In a tab that only shows a script open in another tab, Save, Save As, Open a file, and New are turned off, and say to choose "Edit here instead" first. That tab may show old text.
- Revised the design documents to v0.2 after a pre-implementation review:
  - The parser reads two common mistakes leniently: a heading or transition with no blank line after it, and a parenthetical wrapped across lines. Each is flagged for a Strict Fountain lint rule that rewrites the source into spec form.
  - Notes end at the first blank line, per the spec, and an unclosed `[[` stays literal text.
  - Every edit triggers a full reparse; the windowed incremental design is set aside.
  - The parse result gains `doc.trailing`, so printing is lossless for files that end in a newline, plus parse diagnostics for `drafter check`.
  - Templates gain a reserved `omit` role for elements that never print, a physical paper size, exact-name role rules instead of regular expressions, and explicit `extends` merge rules.
  - Pagination rules are now precise: keep-with-next look-ahead, corrected dialogue-split thresholds, engine-added `(CONT'D)` for continued speeches, and no blank pages from forced breaks.
  - Phase 0 tooling is updated: tsdown, Vitest `test.projects`, pnpm 10, `@pdf-lib/fontkit`, `pdfjs-dist`, `@types/node`, and a "Done means" command that works.
  - The kickoff prompt adds rules for changelog entries, commit trailers, and hook setup.
- Saving now works like a desktop app (design, Phase 1): Save and Save As write a `.fountain` file, in place on Chromium and by download elsewhere; leaving with unsaved changes asks first; and an always-on recovery copy in IndexedDB is written as you type, with warnings when the browser blocks it or may clear it. This replaces the earlier policy of never warning.
- Tightened three v0.2 rules found while writing the samples: a character cue is a name plus optional extensions and nothing else, so `MARGARET (60s) sits…` stays action; dual dialogue never takes a continued-speech `(CONT'D)`; and Brave saves by download, because it ships with the File System Access API turned off.
- Developing Drafter now needs Node 22.13 or later (the root `engines` field): `pdfjs-dist` 6, which the PDF tests use, requires it, and the CLI's `commander` 15 requires 22.12. `.nvmrc` still says `22`, which installs the latest 22.x.
- The README marks Phase 0 done and shows how to install, build, test, benchmark, and run `pnpm drafter` from the repository root. PDFs built from `samples/` and `fixtures/` are ignored by Git.
- The README opens with Drafter's share image.
- The roadmap grows:
  - **Phase 1** adds the first visit and its tour, the Inform-style layout, focus mode, typewriter scrolling, a sprint timer, a daily goal, and counts.
  - **Phase 2** adds a Beat Board, storylines, writing statistics by day, and screen time per character. Testing with NVDA and VoiceOver moves to Phase 2. Phase 1 checks accessibility with automated tests and doesn't claim WCAG conformance.
  - **Phase 3** adds imports from Highland, Fade In, and Celtx, and a template for novels.
  - **Phase 4** adds production revisions and alternate versions of a line.
  - **A later phase** adds direct Open and Save for Dropbox and Google Drive. You sign in with those services, never with Drafter.
- The Phase 1 design is approved, and the architecture and technical design now match it:
  - either pane can show any tab
  - the theme is dark by default
  - a file changed elsewhere goes through the new check
  - screen-reader testing starts in Phase 2

  Proof mode, with reader notes kept as Fountain notes and shown like Word comments, joins Phase 4.

### Fixed

- `@drafter/layout` no longer leaves a scene heading or other keep-with-next line alone at the foot of a page when the next block opens with two-space lines. Those lines print blank, but they counted toward the two lines a heading is kept with, so the heading stayed on the page while the block's first words went to the next one. The layout property test found it, rarely (seed `-1435711900`).

### Security

- `@drafter/fountain` now parses hostile input in linear time. Before this fix, a single 4 KB line could stall the parser for seconds through backtracking regular expressions (cue lines, title-page keys, scene numbers), and long paragraphs of unclosed `[[`, deeply nested emphasis, or thousands of note blocks slowed it quadratically. Emphasis nested past 32,767 levels also lost its styling.
- `drafter` (the CLI) prints control characters from scripts, templates, and file names as visible `\u001b`-style escapes, so a hostile file can't send escape sequences to the terminal through a warning or diagnostic, and it won't write a PDF's bytes to a terminal. Fixed-width text output turns C1 control characters into spaces, as it already did C0.
- `@drafter/templates` now validates a template with any number of roles in linear time, and always reports its problems as a `TemplateError`. A template with 200,000 roles took 15 seconds to reject, and one with enough problems overflowed the call stack with a `RangeError` instead.
