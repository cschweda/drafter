# Changelog

All notable changes to Drafter are recorded here, and every push updates this file. Add entries under **[Unreleased]**, grouped as Added, Changed, Deprecated, Removed, Fixed, or Security. The pre-push hook in `.githooks/` rejects a push when none of its commits touch this file.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and packages follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html). When a release is cut, its entries move from [Unreleased] into a new section headed with the version and date, with a short summary above them.

## [Unreleased]

### Added

- `docs`: the desktop app's design (`docs/drafter-desktop-design.md`: Electron, the Linux app first, then Windows and macOS) and the Electron-against-Tauri test on GitHub's Linux runners that chose it (`docs/desktop-spike.md`), and the plan for the Linux app (`docs/plans/2026-10-27-phase1-plan6-desktop-linux.md`).
- `docs`: the Lighthouse scores at v0.3.0, under that release, and the mobile layout shift they found, in `docs/DEFERRED.md`.
- `apps/desktop`: **the desktop app's shell** (Phase 1 Plan 6, Task 1), a new workspace package, `@drafter/desktop`. Drafter runs in an Electron 45 window from its own files: the same static build as drafter.dev, made with `DRAFTER_DESKTOP=1` and served from `app://drafter/` with the site's content security policy, so it never loads anything from the network. The window is sandboxed and context-isolated with no Node in the page; it stays on the app, sends https links to the system browser, and opens the app's own help pages in a window of their own. One instance runs at a time. `pnpm desktop:dev` builds and starts it; `pnpm --filter @drafter/desktop e2e` tests it with Playwright's Electron driver, each test in a fresh profile.
- `apps/web`: a build for the desktop app (`DRAFTER_DESKTOP=1`) has no service worker and no web app manifest (`scripts/check-build.mjs` checks it), and doesn't warn that the recovery copy may be cleared, since the desktop app's profile never is. `app/desktop.ts` is the one place the web app asks whether it's in the desktop app. drafter.dev's build is unchanged.
- `apps/desktop`: **real files** (Phase 1 Plan 6, Task 2). Open and Save use the system's own dialogs, which start in the folder you last used (else Documents), and Drafter reads and writes the file by its path, so a script you saved keeps saving to its file after a restart, with nothing to allow again. Every save is atomic: the new text goes to a temporary file beside yours, is flushed to disk, and replaces the file in one step, so a full disk, a read-only folder, or a crash halfway leaves your file as it was; the file keeps its permissions, a symlink stays a link, and a file you made read-only is left alone. Files with spaces, accents, other scripts, or a leading dot in their names, and folders reached through a link, work. Line breaks and a byte-order mark are kept, as on the web. While Drafter is showing, a change another program makes to the open file (a sync from another computer, or an editor that saves by replacing the file) is noticed within a moment: **Updated from …**. Export saves where you choose, and a file dropped on the window opens and saves in place.
- `apps/desktop`: **Drafter reads and writes only files you chose**: in its Open or Save dialog, by dropping them on the window, or (soon) by opening them from your file manager or the command line. It remembers them, so your scripts keep saving after a restart, and it checks each time that the file is still the one you chose (one swapped for a link to another file is refused). It writes only scripts and exports (`.fountain`, `.md`, `.markdown`, `.txt`, `.pdf`), so a name typed in the Save dialog without one of those extensions gets one, with a number added rather than replacing another file.
- `apps/desktop`: **spellcheck works on Linux, offline**: the app brings its own US English dictionary (from SCOWL) instead of downloading one, so the Spellcheck setting does something there and no request goes to Google. The app also refuses every permission it doesn't use (camera, microphone, location, notifications, devices, and the like), cancels any web request a page makes (the update check, from the app itself, is unaffected), sends drafter.dev's Permissions-Policy and Referrer-Policy with its pages, and never serves a file from outside its own build. Launching Drafter again when its editor window was closed but another of its windows was open brings the editor back.
- `apps/web`: a save that fails for a reason the system gives says it: "Couldn’t save the file: the disk is full. The file on disk is as it was." (the desktop app).
- `apps/desktop`: **open scripts from your file manager or the command line** (Phase 1 Plan 6, Task 3). `drafterdev Script.fountain` (or double-clicking a script, once the app is installed) opens the file in the Drafter window, which comes forward; starting Drafter again while it runs hands the files to the window that is open instead of starting a second one. A file that is already open is shown, not opened twice (links to it count), and the script you had on show is kept as it is when you choose Open. A file that isn’t a script, or isn’t there, is said in the status bar: “Drafter can’t open “x.png”: it isn’t a script.” macOS’s open-file event is wired for the macOS build.
- `apps/desktop`: **a menu bar** (Phase 1 Plan 6, Task 4): File, Edit, View, Go, and Help, built from the same command list the palette and the Keyboard shortcuts page use, so every item runs its registered command and shows its keys. Choosing an item runs what the palette would; items for commands that don't apply right now are greyed, and the menu follows as you write. File has New, Open, Save, Save As, the samples, templates and exports, and Quit (Ctrl+Q); Help has Keyboard Shortcuts, Saving, and Privacy (each in a window of its own), Take the tour, Open the Releases Page (in your browser), and About Drafter. Script modules' commands stay in the palette for now.
- `apps/web`: `commands/desktop-menu.ts` sends the desktop app the built-in commands and which of them apply (debounced), and runs the one a menu item chooses.

### Fixed

- `apps/desktop`: **a dropped or named file is judged by where it leads**, not by its name: a link called `notes.md` that points at a private file is no longer opened (it was the way past the “only scripts” rule).
- `apps/desktop`: a script with a very long name (about 230 bytes, such as 80 Chinese characters) saves; leftover temp files from a write that was interrupted are cleared by the next save of that file; grants for files on a drive that isn’t mounted at launch are kept; copying no longer asks for a permission nothing needs.
- `apps/desktop`: a file you open as “All files” that isn’t a script type (`letter.rtf`) opens as a new script, with a note saying so, instead of failing to save every time; an unreadable file says “read”, not “write”.

## [0.3.0] - 2026-10-26

**Writing aids, a welcome, and help.** Phase 1's web app, apart from the final accessibility pass:
- **Focus mode** (the Focus button, or Mod+Shift+Enter): your script alone, in a centered column.
- **Typewriter scrolling**: the line you're on stays in the middle of the pane.
- **Counts and a daily goal**: pages, scenes, words, and running time, and progress such as "1.5 of 3 pages today".
- **Sprints** of 15, 25, or 45 minutes, or any length, that say what you added.
- **A first visit** opens the sample on its first scene, with a welcome and a two-minute guided tour you can skip.
- **Offline**: after the first visit Drafter works with no connection and can be installed as an app; a new version waits for you to choose to reload.
- **Help pages**: Saving and your browser, Keyboard shortcuts, and Privacy.

### Added

- `apps/web`: **focus mode**. The toolbar's **Focus** button, **Toggle focus mode** in the palette, and Mod+Shift+Enter hide the toolbar, the tabs, the bars, the status bar, and the other pane, and show the Source alone in a centered column 64 characters wide, with the cursor in it (Markdown documents and phones too). **Esc** leaves once nothing else needs it (CodeMirror's completion or search panel, the palette, a menu, a dialog, an input method); so does the same command or key, and the **Leave focus mode** button in the corner, for a phone. The corner marker says **Saved** or **Unsaved changes** (**Read-only** in a tab that can't edit), the sprint's time left, and what the hidden bars would have said: a failed save, "changes exist only in memory", a missing or locked file, and **Updated from …** after a file changed elsewhere. The tab title keeps its dot. It never asks for full screen, and under reduced motion nothing animates.
- `apps/web`: **typewriter scrolling**, off to begin with. After each change or cursor move you make, the line you are on is scrolled to the middle of the Source pane (on a phone, the middle of the part above the keyboard), with room above and below the text so the first and last lines can get there. A **Typewriter** button on the Source pane's bar, **Typewriter scrolling** in Settings, and the palette set it, and Drafter remembers the choice. It works with or without focus mode and in Markdown documents. It never fights the mouse wheel, a click, a finger on a selection handle, or Select All.
- `apps/web`: **counts and a daily goal**. The status bar's page item is now a button that opens a **Counts** panel: pages (to one decimal, the title page left out), scenes, words, and running time at a page a minute. Words are the text that prints: notes, the boneyard, sections, synopses, and the metadata block don't count. The panel also sets a **daily goal** in pages or words (words only in a Markdown document, and none on a sample or in a read-only tab), and the status bar shows **1.5 of 3 pages today** or **420 of 1,000 words today**. Progress is how much the script has grown since the day began, so a cut counts against it; the day rolls over at local midnight, and each script keeps its own goal in this browser.
- `apps/web`: **sprints**. **Start a sprint** in the Counts panel (15, 25, or 45 minutes, or any whole number from 1 to 180) or from the palette. The time left shows in the status bar and focus mode's corner with **Pause**, **Stop**, and **Hide**, and a screen reader is never told it as it changes. Time is kept by the clock, so it stays right in a background tab. When time is up a toast and one polite announcement say what it added, such as **Sprint done: 312 words (1.2 pages).**, and the Counts panel keeps the last sprint's result. A short tone plays only if **Sprint sound** is on in Settings (off to begin with).
- `apps/web`: **the first visit**. A browser with no scripts opens the screenplay sample with the cursor on its first scene heading, and the Script pane shows the same place. A **Sample** bar above the panes, on every tab, says "This is a sample. Start your own:" with **New screenplay**, **New stage play**, **New Markdown document**, and **Open a file…** (one row with a **More** menu on a phone). **Reset sample**, in the palette and the Drafter menu's Help section, puts the sample's own text back as one change that Undo takes back. A browser whose storage can't be read is never treated as a first visit.
- `apps/web`: **the welcome dialog and the guided tour**, built with `nuxt-guided-tour`. A first visit is welcomed once with **Take the tour** or "No thanks, I'll look around."; the tour is "Fountain in 30 seconds" and then ten steps, each lighting its part of the screen. It can be skipped from its first screen, works from the keyboard and with a screen reader, and comes back only from **Help → Take the tour** or the palette. On a phone a step switches to its pane first. It leaves focus mode, waits for a dialog or the palette to close, and under reduced motion doesn't pulse.
- `apps/web`: **offline use and updates**. A service worker (`@vite-pwa/nuxt`, Workbox) precaches the app's own files (the page, its scripts and styles, the workers, the fonts, the icons, and the help pages) and caches nothing else, so Markdown documents and PDF export work offline too. A web app manifest lets a browser install Drafter. When a new version is deployed, a toast says "A new version of Drafter is ready" with **Reload** and **Later**; Drafter never reloads by itself, and only the tab whose writer chose Reload reloads. With changes that aren't in a file, Reload asks first and offers **Save first** (in a browser that downloads, it waits for the download), **Reload anyway** (the recovery copy is brought up to date first), and **Cancel**. `scripts/check-build.mjs` checks the precache, and `_headers` keeps `/sw.js` and the manifest from being cached.
- `apps/web`: **install advice for your browser.** The storage warning tells Chrome and Edge to use **Install** in the address bar, Safari to use File → Add to Dock on a Mac or Share → Add to Home Screen on an iPhone or iPad, and an installed app only to save to a file, found by what the browser can do, never by its name.
- `apps/web`: **help pages**, prerendered at `/docs/saving/`, `/docs/shortcuts/`, and `/docs/privacy/` with a `/docs/` index, readable without JavaScript and offline, in the app's themes. **Saving and your browser** covers what Save does in each browser (Chrome and Edge on a computer save in place; elsewhere it downloads), synced folders, the check for a file changed elsewhere, the recovery copy, and installing. **Keyboard shortcuts** lists every built-in command, for a Mac and for Windows, Linux, and ChromeOS, from the command data itself (`app/commands/data.ts`). **Privacy** says plainly what Drafter keeps and where, and that a script never leaves the device. They open in a new tab from **Help** in the Drafter menu and from the palette.
- `apps/web`: **the template, from the Drafter menu**: a **Template** section (Screenplay, Stage play, and Markdown), the chip's own list, so a phone can choose one.
- `apps/web`: **a template Drafter doesn't have says so.** A script whose metadata block names one is shown as a screenplay as before, and now the chip, the status bar, and the Drafter menu read **Screenplay (fallback)** and say "This script asks for “my-own”, which Drafter doesn't have, so it's shown as a screenplay." (the name shortened and cleaned of control characters).
- `apps/web`: `e2e/keyboard.spec.ts`, a keyboard-only journey (a new screenplay, a scene, go to it, fix a problem, a stage play and back, save, export a PDF) with no pointer event at all.

**Lighthouse at release** (drafter.dev, lightcap): desktop 100 performance, 100 accessibility, 100 best practices, 100 SEO; mobile 93, 100, 100, 100 (a 0.15 layout shift as the bars above the panes appear, listed in `docs/DEFERRED.md`).

### Fixed

- `apps/web`: in Safari, widening or narrowing the window while the cursor was in the Source pane put the cursor back at the start of the text, so the next key typed landed there. The cursor now stays where it was.
- `apps/web`: **Template: Screenplay** is offered in the palette for a script whose template Drafter doesn't have, so the fallback can be replaced from the keyboard.

## [0.2.0] - 2026-10-26

**The full editor.** Everything around the writing:
- **The command palette** (Mod+K): every command, every scene, and Go to line, with one set of keys shared by the palette, the menus, and the keyboard.
- **The app menu** on the Drafter mark, and **Revert to Saved**, which one Undo takes back.
- **Settings**, kept in your browser: text size, spellcheck, Strict Fountain, match system appearance, and line numbers (off to begin with).
- **The Problems pane:** every problem with its line, a fix where there is one, and **Fix all** in Strict Fountain.
- **Templates and documents:** Screenplay, Stage play, and **plain Markdown documents** with a live preview, chosen from the toolbar or the palette.
- **Export** to PDF and plain text (a Markdown document exports its `.md` file and plain text).
- **A file changed elsewhere** (by Dropbox on another computer, say) is noticed, and both versions are kept when both changed.
- **Script modules:** optional features you turn on in Settings → Modules, with three samples: Scene list, Cast, and Notes. In your own copy of Drafter, a module dropped into the `modules/` folder appears after a restart.

### Added

- `apps/web`: the command palette. Mod+K (or the toolbar's search field) opens it from anywhere, the editor included. It lists the scenes by their heading text with their source lines, "Go to line N" when you type a number, and every command that applies, with its keys. Esc closes it and focus goes back where it was.
- `apps/web`: a command registry (`registerCommands`, `useCommands`, `formatKeys`). File, Edit, View, and Go commands, among them New screenplay (Mod+Alt+N), New stage play, Open (Mod+O), Save, Save As, Remove from this browser, Next and Previous problem (F8, Shift+F8), Show Source, Show Script, Show Problems, Switch theme, Fold all, Unfold all, Undo, Redo, Find, and the Fountain commands (make a scene heading through a lyric, dual dialogue, wrap in a note, cut to the boneyard). A command that is off can say why, and the app menu shows the reason beside it.
- `apps/web`: Shift+F8 goes to the previous problem, and Mod+Shift+Z redoes on every platform.
- `apps/web`: settings, kept in this browser (IndexedDB) and set from a Settings dialog (File > Settings…, Mod+,): match system appearance, text size (90% to 150%, scaling the Source pane and, at 100%, the Script pane), spellcheck, Strict Fountain (its rules become warnings at once), and line numbers. If the browser can't store them, the defaults apply and writing carries on.
- `apps/web`: line numbers in the Source pane, off to begin with, in the leftmost gutter. A "Line numbers" button on the pane's bar, the Show and Hide line numbers commands, and the dialog toggle them, and Drafter remembers the choice.
- `@drafter/fountain`: `setMeta(doc, meta)`, the text changes that write the `/* drafter … */` metadata block, replacing the existing one or appending one, with the script's own line break and every `/` in the JSON escaped so no value can close the block. It writes nothing while a `/*` is unclosed.
- `@drafter/lint`: `similar-names` offers **Mark as distinct**, which adds the pair to `meta.distinctNames`, and no longer reports names whose one edit falls inside a word of three letters or fewer (`MR. SMITH` and `MRS. SMITH`, `JOHN JR.` and `JOHN SR.`, `GUARD A` and `GUARD B`).
- `apps/web`: a file changed somewhere else, such as by Dropbox on another computer, is noticed when a script opens, when the window regains focus, and before Save writes, never mid-sentence. If only the file changed, its text replaces the editor's as one undoable change ("Updated from The Call.fountain."). If both changed, a dialog asks which to keep working on, **Open the file** or **Keep this browser's version**, and the other is kept as a new script, with the text as it is when you answer. Save never overwrites a changed file. A script whose file Drafter may not read yet opens read-only under a bar with **Check for changes** (choose "Allow on every visit" when Chrome offers it, and the check is automatic), and one whose file is gone offers **Save As** or **Edit this browser's copy**.
- `apps/web`: **Export**, from the toolbar, the app menu, and the palette: **PDF** and **Plain text (.txt)** for a script, the **Markdown file** and plain text for a Markdown document. The pages are laid out and drawn in a worker, with Courier Prime fetched once from the app's own origin, and saved where you choose (Chromium's save picker, suggesting the title as the file name), or downloaded in other browsers. The plain text is what `drafter build --txt` writes. A toast says when the file is ready, or why it isn't; an empty script says "Nothing to export yet." An export waits for a script switch in progress, so the name and the pages are one script's.
- `apps/web`: the Problems tab lists what the Source gutter marks, each with its severity, message, and line. Choosing one selects its text in the Source pane, and a problem with a fix has a button for it (a fix only applies to the text it was found in). The tab shows a count of errors and warnings, the status bar reads "No problems", "1 problem", or "N problems", and with Strict Fountain on a **Fix all** button applies every Strict fix in one undoable change. The list keeps its place and your focus while you type, and a read-only tab offers no fixes.
- `apps/web`: the template chip in the toolbar is a menu. **Screenplay** and **Stage play** are checked items; choosing one writes `template` into the script's `/* drafter … */` block as one undoable change, and the pages and the lint rules (a stage play has no scene-time or last-transition warnings) follow at once. The palette has **Template: Screenplay** and **Template: Stage play**, which is how a phone, where the chip is hidden, switches.
- `apps/web`: plain Markdown documents. **New Markdown document** (Scripts menu, app menu, and palette, after New screenplay and New stage play) starts with `# Untitled`. The Source pane uses CodeMirror's Markdown mode (Fountain's keys, completion, folding, and lint are off), the Script tab becomes a **Preview** drawn from a CommonMark parse with no HTML strings (raw HTML shows as text), the status bar counts words, and the Problems pane says "No checks for Markdown documents." `.md` and `.markdown` files open as Markdown and save as `.md`. The template chip lists **Markdown (plain text)** last: choosing it for a script asks first, and choosing Screenplay or Stage play turns Fountain back on, keeping the text. After a change of type, the next Save asks where to save, suggesting the right extension. The Markdown mode and parser download only when a Markdown document is first used. `@codemirror/lang-markdown` and `mdast-util-from-markdown` are new dependencies, listed in `docs/DEPENDENCIES.md`.
- `apps/web`: the app menu. The Drafter mark in the toolbar is now a button ("Drafter menu") that opens New screenplay, New stage play, New Markdown document, Open…, the recent scripts, the samples, Save, Save As…, Revert to Saved, Export, and Settings…, each with its keys. Every item runs its registered command, so the menu, the palette, and the keys agree.
- `apps/web`: **Revert to Saved** (File, the app menu, and the palette) puts the text last saved to the script's file back as one change, so one Undo brings your changes back, and says "Reverted to the text last saved to The Call.fountain. Undo brings your changes back." It is available only while the script has changes and a saved file of the same type to go back to.
- `apps/web`: script modules, optional features compiled into Drafter. A module is a folder in the new `modules/` folder at the repository root (`modules/README.md` explains how to write one and how to install one in your own copy); its `index.ts` default-exports a `ScriptModule`. **Settings → Modules** lists each module with an on/off switch (off to begin with, remembered), and a module that would send your script to another site asks first, in plain words, and again if it later asks for more. A module that's on adds a toolbar button, a tab beside Source, Script, and Problems, palette commands under its name, and a section in Settings. It reads the script through `ModuleContext` and changes it as one undoable step; a run that outlives its script or the text it began with can't change anything, and a module that throws shows a message and breaks nothing. `modules/` is typechecked with the app, and the content security policy is unchanged (`connect-src 'self'`).
- `modules/`: three sample modules, written only against `ModuleContext` so they double as examples, off until turned on, needing no network. **Scene list** lists every scene, numbered, with its page and its length in eighths of a page. **Cast** lists every character with their speeches and the scene of their first appearance, and can copy the list. **Notes** lists each `[[note]]` in the Problems pane with its line, and can remove them all as one undoable change after asking how many. Their tests run in a new `modules` Vitest project.
- `apps/web`: the browser tests' server port can be set with `E2E_PORT`, so two working copies can run their suites at once. Accessibility checks in the browser tests run with `A11Y=1` (`pnpm e2e:a11y`) until the final accessibility pass.

### Changed

- `apps/web`: Save, Save As, Open, New screenplay, and the palette have their keys through the command registry, on the whole page, one handler for each key. Mod+S and Mod+Shift+S no longer have a second binding in the editor's keymap.
- `apps/web`: the Scripts menu's New items, the app menu, the template chip, and the palette are made from one list of document types, in one order: Screenplay, Stage play, then Markdown.

### Fixed

- `apps/web`: the remove and same-title dialogs opened at the top left of the window, because Tailwind's reset removed the automatic margin that centers a `<dialog>`; every dialog opens in the middle again.

## [0.1.0] - 2026-10-26

**Write and keep your work at drafter.dev.** The first version you can write a script in:
- **The editor:** Fountain in CodeMirror, with highlighting, the Fountain keys, name and place completion, folding, and lint markers.
- **The pages:** the real pages, laid out as you type, exactly as the PDF will print.
- **A recovery copy** of your script, kept in your browser as you type.
- **One tab at a time:** a script edits in one tab, and opens read-only in any other.
- **New screenplays and stage plays,** and switching between your scripts.
- **Save, Save As, and Open** for `.fountain` files: in place on Chrome and Edge, by download elsewhere, keeping a file's line breaks.

It also includes Phase 0's engine and command line, and the editor packages behind the app.

### Added

- Release v0.1.0: every package and the app at version 0.1.0, a `v0.1.0` tag, and a GitHub release.
- The README links [Inform 7](https://ganelson.github.io/inform-website/) wherever it names it, and credits its IDE (its layout and ease of use, not interactive fiction itself) as an inspiration.
- A screenshot of the editor at the top of the README, in the dark and light themes (`docs/images/`), shown to match the reader's GitHub theme, and a link to drafter.dev.
- Design documents in `docs/`: the high-level architecture, the technical design, and the Phase 0 kickoff prompt.
- README covering the vision, principles, architecture, packages, and the phased roadmap.
- MIT license.
- `.nvmrc` pinning Node 22.
- `.gitignore` for a pnpm, Node, and Nuxt monorepo.
- Pre-push hook (`.githooks/pre-push`) that rejects a push unless at least one of its commits updates this changelog.
- Sample scripts in `samples/`: a short screenplay and a short stage play that tell the same story, with notes in the source explaining each piece of Fountain.
- Phase 0 workspace: pnpm 10, TypeScript 5.9 (strict, ESM), Vitest 5 with one project per package, tsdown builds, Biome, and fast-check.
- `@drafter/fountain`: the lossless Fountain parser. `parse`, `reparse`, `print`, `toJSON`, `blockAt`, `characters`, and `locations`, with diagnostics for unclosed notes and boneyard, invalid metadata, and lenient readings. Tests cover 41 hand-written classification fixtures, 10,000 arbitrary strings for round-tripping, and 1,000 random edit sequences for `reparse`; `pnpm bench` times a 200 KB parse (about 1.5 ms against a 5 ms budget).
- `@drafter/fountain`: `line.transparent`, so pagination can tell a line holding only a note from a blank line inside a speech, and styled `runs` for title-page values.
- `@drafter/templates`: the template schema and loader, with inch conversion, `extends` merging, and validation that reports every problem with its path; `resolveRole`; and the `us-screenplay` and `stage-play-standard` built-ins.
- Layout fixtures in `fixtures/layout/`: seven scripts with hand-derived page positions and the arithmetic behind them, written and reviewed before the layout code existed.
- `@drafter/layout`: `paginate` and `wrap`. Lays a parsed script out on pages as a template describes: word wrap, keep-with-next look-ahead, speeches split with `(MORE)` and `(CONT'D)`, the continued-speech `(CONT'D)`, dual dialogue, scene and page numbers, forced breaks that never make a blank page, and the `centered-feature` title page. Tested against the seven layout fixtures, structural properties over generated scripts in both built-in templates, and hostile inputs that must lay out in under a second; `pnpm bench` times a 190-page script at about 7 ms.
- `docs/DECISIONS.md` and `docs/DEFERRED.md`, recording choices the design leaves open and work saved for later phases.
- `@drafter/render-pdf`: `renderPdf(layout, template, { fonts })` draws laid-out pages as a PDF at the template's paper size, with Courier Prime embedded as subsets of only the styles a script uses, underlines, page and scene numbers, headers and footers, and the title page's title as the document title. It reads no files, so it runs in Node and in a browser worker, and the same layout always gives the same bytes. Courier Prime's four styles ship in the package's `fonts/` folder under the SIL Open Font License, with their source and checksums recorded. Tests read every layout fixture back with pdfjs and find each line within half a point of its grid position.
- `@drafter/cli`: `drafter build` writes a script as PDF, fixed-width text, or JSON, choosing the template from `--template`, the file's metadata block, or `us-screenplay`, with `--scene-numbers` and `-` for standard output. `drafter check` lists every parse and layout diagnostic as `file:line:column` and exits 1 on any error. The root `pnpm drafter` script runs it from the repository root; tests run it that way too, covering the kickoff's acceptance tests 9 and 11 and its "Done means" command.
- Drafter's visual identity, in `brand/`: the mark (plain-text source on one side of a line, the formatted script on the other, on a tile of revision-page colors), the "drafter" wordmark in Inter Tight, a palette taken from the colors of revised script pages, a 1200 × 630 share image for links (`og-image.svg` and `.png`), navbar logos for dark and light backgrounds, and favicons and app icons from 16 to 512 px. - `@drafter/lint`: `lint(doc, template, options)` returns a parsed script's problems sorted by position, each with a rule id, a severity, the text it is about, a message, and sometimes a fix: a list of text changes in the script's own offsets. It starts with the parser's diagnostics, as four rules.
  - **Rules:** `unclosed-region` (an error for a boneyard, a warning for a note), `invalid-meta` (a warning), and the Strict Fountain rules `heading-blank-after` and `multiline-parenthetical` (info).
  - **Fixes:** *Insert a blank line* and *Join onto one line*. Both keep the file's line endings, CRLF included. A heading whose line break falls inside a note or a boneyard is reported with no fix: a blank line in a note would end it, and one in a boneyard would leave the text below the heading where it was.
  - **Options:** `strict` raises the Strict rules to warnings, and a template's `lint.disable` and the `disable` option turn rules off by id.
  - **Tests:** every rule's hits and non-hits; properties over generated scripts for the fixes (each settles its own problem, all can be made at once, and none changes a line ending); and hostile files that must lint in under a second.
- `@drafter/lint`: four more rules, for mistakes the parser can't see on its own.
  - **`character-without-dialogue`** (warning): an upper-case line shaped like a cue (`MARGARET`, `BRICK (V.O.)`, `HANS (on the radio)`), alone in its block, followed by one blank line and an action block that opens with a parenthesis or is about a character cued elsewhere in the script. The parser reads it as action, and the fix, *Remove the blank line*, makes it a cue. Forced action (`!`) and lines with emphasis are left alone.
  - **`manual-contd`** (info): a `(CONT'D)` typed on a cue where the layout would add one itself: the template continues speeches after action, and the same speaker spoke earlier in the scene. So it says nothing on the first speech in a scene, after someone else's, on dual dialogue, or in the stage play. The rule makes the layout's own decision, and a test checks it against `paginate` in seven templates. The fix, *Remove (CONT'D)*, takes out every one on the cue, with the spaces before it.
  - **`heading-no-time`** (warning): a scene heading with no time of day. A forced heading (`.MONTAGE`) is how Fountain writes one without, so it is never reported, and the stage play turns the rule off.
  - **`transition-not-last`** (warning): a transition that isn't followed by a scene heading, a section, or a page break. Notes, boneyard, synopses, and centered text between them are skipped, so `>FADE OUT.` then `> THE END <` passes, and a transition that ends the script passes. The stage play turns this rule off too.
  - **Tests:** hits and non-hits for every rule; the cue test checked against the parser, and `manual-contd` against the layout, on thousands of generated scripts; properties that each fix settles its own problem and keeps the file's line endings; the rules on the classification fixtures; and a 200 KB hostile script, with thirteen other hostile files, that must lint in under a second.
- `@drafter/lint`: the `similar-names` rule (info), the last of Phase 1's rules. It finds two character names one edit apart, such as `MARGERET` beside `MARGARET`, which are probably one character typed two ways, and says so: `"MARGERET" is one letter from "MARGARET", which has 12 cues. A typo?`
  - **When:** both names have at least five letters, one is cued twice or less, and neither is the start of the other. So `MAX` and `MAC` (too short) and `DANNY` and `DANNYS` (a prefix) are left alone. An edit is a letter changed, added, or left out, or two letters side by side swapped, counted in code points, so an emoji is one. Names that differ only in case, such as `@McCLANE` and `MCCLANE`, are one name, and their cues add up. Names that differ only in their digits, such as `GUARD 1` and `GUARD 2` or `GUARD 12` and `GUARD 2`, are numbered characters and are never reported, in any script's digits; `AGENT 47` beside `AGENT47` differs by a space, and still is.
  - **Where:** once for each pair, at the first cue of the rarer name, or of the one that first appears later when they tie. There is no fix.
  - **Marked as distinct:** a pair listed in the metadata block's `distinctNames`, such as `[["MARGARET", "MARGERET"]]`, is never reported, in either order and in any case. A `distinctNames` that isn't a list of pairs is ignored.
  - **Speed:** only names that share a key are compared, where a name's keys are its letters and its letters with any one code point left out, so the work grows with the number of names, not its square. A name of more than 32 code points isn't compared, and neither is a group of more than eight names that differ in one place, a series such as `SOLDIER A` to `SOLDIER I`, so a hostile file can't slow the linter or flood the report.
  - **`withinOneEdit(a, b)`** is exported: whether the restricted Damerau-Levenshtein distance between two strings is at most 1.
  - **Tests:** hits and non-hits for each condition and each kind of edit; ties, and counts that add up across spellings; a `distinctNames` of every wrong shape; numbered characters left alone, and typos beside them still found; differential properties, over names with and without digits, that the index finds exactly the pairs that comparing every name with every other finds, and that `withinOneEdit` agrees with the full distance table; and twenty thousand names, thousands of them a pair, found in under a second, with a count worked out another way.
- `@drafter/render-html`: the Script pane's renderer, which draws a layout's pages as accessible DOM. Each line that prints is its own element, placed by row and column on the character grid the PDF and the text export use, and blank lines aren't drawn. `style.css` positions it all, and takes the paper and the type from the `--drafter-page` and `--drafter-ink` variables.
  - **Reading:** each page begins with a hidden "Page N" marker, or "Title page". Scene headings are level-2 headings, and in the stage play act headings are level 2 and scene headings level 3, read from the templates' `heading`. Each speech is a group labelled by its cue, and a speech that carries on to the next page is labelled there by the cue the layout repeats, `MARGARET (CONT'D)`. Dual dialogue reads the left speech before the right, whichever column is longer, and a title page reads field by field in the order the writer gave them, so a draft date that wraps follows the whole contact block. `(MORE)`, page numbers, scene numbers, headers, and footers are hidden from screen readers.
  - **`speechRoles(template)`** reads which roles open a speech, and which carry it on, from a template's role map, so a template that gives sound cues a role of their own gets its groups too.
  - **Safe text:** script text reaches the DOM only through `textContent`. Control characters and the Unicode line and paragraph separators print as spaces, each keeping its column, as in the PDF and the text export.
  - **The view:** `createScriptView(container, options)` adds the labelled Script region, and `update(layout, template)` draws into it. The first call waits for the fonts, and draws anyway if they fail to load. After that it replaces only the pages that changed (each is compared as JSON, and a different template changes them all) and removes the pages that are gone, so an unchanged page keeps its element. A page that only moved in the source, as every page after an edit that changes the script's length has, keeps its element too, with its source offsets and block numbers moved in place: on a script of 121 pages, an edit on the first costs 2 ms in Chrome, against 19 ms to build the pages again. When calls overlap, the newest wins. A script with no pages clears the view.
  - **Clicks and the cursor:** a click on a line dispatches `drafter:goto` with the line's source offset. `reveal(blockIndex)` scrolls the line where a block starts into view, choosing it by row, and leaves the view alone for two seconds after the reader scrolls the container by wheel, touch, or key. The tests cover each of these, the fonts failing, overlapping updates, a CRLF script, and a layout of ten thousand pages and a page of twenty thousand lines that must update and reveal in under a second.
  - **Tests:** the whole contract in jsdom; properties over generated scripts in both built-in templates (every line that prints is drawn once, where the layout puts it; each speech is named from inside; only `(MORE)` and the furniture are hidden; dual dialogue's two columns stay whole across pages); and hostile pages (a cue of twenty thousand lines, ten thousand speeches, and ten thousand rows of dual dialogue) that must build in under a second. `jsdom` and `@types/jsdom` are new development dependencies, for these.
- `@drafter/cm-fountain`: Fountain in CodeMirror 6, starting with the parse in the editor's state and the highlighting read from it. `@drafter/fountain` is still the only parser, and there is no Lezer grammar. The five CodeMirror packages it uses are general-purpose editor libraries, listed in `docs/DEPENDENCIES.md`.
  - **The parse:** `parsedDoc` is a state field that holds the parse of the text, `parse` when the state is created and `reparse` on every change, so every other editor feature reads it and none parses again. It parses the text with `\n` between the lines, whatever the file used, so the parser's offsets are CodeMirror's positions, even when an app sets `EditorState.lineSeparator`.
  - **The highlighting:** `fountainDecorations(state, ranges)` builds the decorations for the ranges given, and `fountainHighlighting()` is the view plugin that keeps them for the visible ranges, folded ranges included.
    - Each line gets `cm-f-<kind>` for its block (`cm-f-scene_heading`, `cm-f-character`, and so on), and each title page line gets `cm-f-title`, with `cm-f-title-key` on each field's `Key:`.
    - Each styled run gets `cm-f-b`, `cm-f-i`, or `cm-f-u`, and each note and boneyard gets `cm-f-note` or `cm-f-boneyard`.
    - Every other character a line doesn't print, except whitespace, gets `cm-f-marker`, so a theme can dim it: forced markers, `#`, `=`, `^`, emphasis markers, scene numbers, and escapes. `INT. HALL - DAY #12#` dims `#12#`, and `**bold**` dims each `**`.
    - Only the blocks that touch the ranges are decorated, so a keystroke costs the lines in view and not the script.
  - **Tests:**
    - The parse equals a fresh one after 200 random sequences of multi-range edits, and with CRLF text and each line separator.
    - Every character that isn't whitespace, in the generated scripts, the repository's fixtures and samples, and strings made of the characters that mean something, is printed, in a note or boneyard, in a key, or a marker, found by comparing the decorations with the parser's own runs.
    - A view in jsdom shows the classes, follows edits, and decorates what an unfold shows again.

- `@drafter/cm-fountain`: the Fountain keymap and the input filters, which read their context from the parse in the editor's state. Each command is one transaction, so one undo step, and none indents: they insert the file's own line break, `\r\n` for a CRLF file.
  - **Enter:** a plain line break, or two at the end of a scene heading or a transition, since a heading is always followed by a blank line. Just before the `)` of a parenthetical, the cursor first moves past it. A selection is replaced by one break, and every cursor gets its own.
  - **Tab and Shift-Tab:**
    - Tab on an empty line after a blank one starts a cue, with an `@` and cue mode. On an empty line under a cue or a speech it opens a parenthetical, `(|)`.
    - Tab on a cue cycles `(V.O.)`, `(O.S.)`, and none, and on action with text it makes the line a cue, upper-cased, as the named command `convertToCharacter`. Shift-Tab on a cue is `convertToAction`: no `@`, and lower case but for the first letter.
    - Tab does nothing, and so the browser's own Tab moves focus, wherever the table of technical design §3.3 gives it no meaning: a heading, a transition, a line of speech, a note, the title page, a selection, and so on. The editor doesn't trap the keyboard.
  - **Other keys:** `Mod-Alt-1` to `7` force a line's kind (heading, action, cue, parenthetical, transition, centered text, lyric), replacing the marker or wrapper it has and never changing case. `Mod-Shift-d` toggles `^` on the cue of the speech the cursor is in. `Mod-/` and `Mod-Shift-/` wrap the selection in a note or a boneyard, or insert an empty pair with the cursor inside. The save keys are the app's.
  - **Input filters:** `fountainInput()` upper-cases what is typed in a cue started with Tab and in a scene heading after its prefix, and nowhere else. `cueMode` is on from the Tab until Enter, until the cursor leaves the line, or until the `@` is deleted. Only typing is changed, as it is typed, over whole code points, surrogate pairs included. Text already in the document, a paste, a completion, and a change the app makes keep their case.
  - **Notes and boneyards:** one typed on a scene heading or a cue line stays as typed (`INT. HALL - DAY [[check the location`), and forcing the kind of a file's first line keeps its byte-order mark.

    - Every row of the keymap table; the keys pressed in a jsdom view; and a Tab that must pass through, unprevented, wherever it has no meaning.
    - The edge cases of each command, and a scene typed from the keyboard that the parser reads as the writer meant.

    - Lines of 200,000 characters, a block of 100,000 lines, a speech of 50,000 lines, and 20,000 cursors, which must be handled in under a second.
- `@drafter/cm-fountain`: autocomplete, with names, places, and titles read from the parse in the editor's state. `fountainCompletionSource` is a CodeMirror completion source, and `fountainCompletion()` is `autocompletion` with it as its only source, bringing `parsedDoc` with it.
  - **Character names:** on a cue line, which is a line under a blank one that starts with `@` or has two letters and none in lower case. The name whose last cue before the cursor is nearest comes first, then the names with the most cues. After a name and a space, or from an open `(`, it offers `(V.O.)`, `(O.S.)`, and the extensions the script uses, each on its own. A name that needs an `@` to be a cue, such as `McCLANE`, is offered only after one.
  - **Places and times:** after a scene heading's prefix and a space, the script's locations, the most used first. After ` - `, its times of day, then `DAY`, `NIGHT`, `CONTINUOUS`, `LATER`, and `MOMENTS LATER`.
  - **Transitions and sections:** on a line that starts with `>`, the script's transitions, then `CUT TO:`, `DISSOLVE TO:`, `SMASH CUT TO:`, and `FADE OUT.`. After `#`, its section titles.
  - **Where:** the parser reads a cue that is still being typed as action, so where the cursor is comes from the text of its line, by the parser's own rules, and what to offer comes from the parse.
  - **When:** the list opens when asked (Ctrl+Space), or once two characters of what is being completed are typed.
  - **Enter:** a name typed in full is not offered, so Enter goes on to the speech and does not accept a list that would change nothing. When the text typed is already one of the names, no list opens at all, even if a longer name starts with it (`DAN` beside `DANNY`): the writer types `DANN` to reach `DANNY`. Case is ignored, and every list works this way. Names are matched from their start, so `OC` doesn't offer `DOCTOR`.
  - **Tests:** what each place offers, and in what order; where a cue line can and can't be; the full name that leaves Enter alone, in the source and in a view with CodeMirror's own completion; and hostile scripts (a hundred thousand different names, places, times, transitions, sections, and extensions, and lines of a million characters) that must be answered in under a second.
- `@drafter/cm-fountain`: folding, the cursor's element, lint, and `fountain()`, which composes the whole package.
  - **Folding:** `fountainFolding()` folds a section to the next section of equal or shallower depth, and a scene to the next heading or section, from the end of the heading to the end of the last block. A folded scene shows its heading and its first synopsis; a folded section shows its title.
  - **Cursor:** `cursorElement(state)` is the block, line, and kind under the main cursor, null on a blank line, and the title page as `blockIndex` -1. `onCursorElement(callback)` calls back when that changes.
  - **Lint:** `fountainLint({ template, options })` runs `@drafter/lint` on the parse 300 ms after typing stops, with CodeMirror's gutter and tooltips, and `toCodeMirror` maps the diagnostics, a fix becoming an action. A launch writes each one that is newer than its script's stored copy and clears the rest, and so does switching to a script from the menu: a tab that closed right after typing leaves its newest text in the stash, and the next tab to open that script shows it and writes it.
  - **Writes:** a write for a script that is no longer open fails, so the writer keeps the text, instead of reporting success. It keeps what else is recorded on the stored project (`writeSource` merges into a fresh read), so a save recorded from another tab isn't undone by the next write.
- `apps/web`: a script opens in one tab at a time.
  - **Holding:** opening a script takes the Web Lock `drafter:project:<id>` and keeps it until the script closes or the tab goes. A second tab finds it taken and opens the script read-only (no typing, no recovery writes, no stash, no leave warning), under a bar that reads "This script is open for editing in another tab".
  - **Edit here instead:** asks the other tab over the `drafter` channel. It writes its recovery copy, turns read-only, and lets go; the asking tab then reloads the script from IndexedDB and applies a leftover stash only if the stash is newer. If the other tab can't write, it keeps the script and the bar says it didn't let go.
  - **No Web Locks, or no `BroadcastChannel`:** no guard; every tab edits, as before.
  - **Switching:** switching scripts takes the new script's lock before letting go of the old one, and the editor can't be typed in during the switch, so another tab can't take the old script while this one can still edit it. A tab handing a script over lets go of the lock it was asked about, not one a switch took meanwhile, and still leaves its unwritten text for a closing page.
  - **Edit here instead is for the script shown when it was pressed:** if another script was opened while the tab waited for the lock, the lock is let go and nothing is taken over; the scripts menu doesn't switch while the handover waits.
  - **The bar is announced:** its text sits in a status region that is always in the page, and its two sentences are punctuated.
  - **Read-only editor:** a lint quick fix no longer changes the text of a read-only editor (`@drafter/cm-fountain`).
- `apps/web`: new scripts, and switching between this browser's scripts and the samples, from the toolbar's **Open** menu.
  - **The menu:** **New screenplay**, **New stage play**, this browser's scripts (most recent first, the open one marked), and **Samples**: Screenplay and Stage play. It works from the keyboard (Enter or Space opens it, Escape closes it and returns to **Open**) and closes when focus or a click leaves it.
  - **A new script** is a title page to fill in (title, credit, author, and today's date), with the cursor ready to type below it. A stage play also carries the metadata block that names its template. It has its own undo history, like every script you switch to.
  - **Untouched new scripts don't count as changed:** a new script remembers the text it started from, so leaving it before you type asks nothing, and typing it back to the template ends the changes.
  - **Samples** open as scripts of their own that stay in this browser with your edits to them. Switching keeps the script you leave first; if it can't be kept, nothing is switched.
  - **Remove from this browser** asks first and says the file isn't touched (and when the script has never been saved to a file, that removing it deletes the only copy; when it has a file but changes since its last save, that those changes are lost). Removing the open script opens the most recent other one, or the screenplay sample. A script another tab has open is never removed, and the menu says so.
  - **Another tab:** switching to a script another tab holds opens it read-only, and the script you left is let go.
  - **One switch at a time:** a double click on New screenplay makes one script, and a second switch can't load over text typed after the first. The menu's items are disabled while one is under way.
- `apps/web`: Save and Save As. **Save** (toolbar, `Mod+S`) writes the script to its file: in place on Chromium, remembered across reloads, and by download in browsers without the File System Access API. **Save As…** (Open menu, `Mod+Shift+S`) asks where. A sample saved this way becomes a script of the writer's own and the sample is left as it was. The status bar reads "Saved just now", "Saved N min ago", "Saved at 3:42 PM", or "Unsaved changes", and the tab title starts with a bullet while there are changes. Files keep their line breaks and byte-order mark. All file access goes through one `FileAccess` interface (`storage/files.ts`) that a desktop build can replace.
  - **Tied to its script:** a save is recorded against the script it started on. If the writer switched scripts while the file was being picked or written, the file still gets that script's own text (read from storage, not from the editor, which shows the other one), and the record of the file's name, handle, and saved text goes to that script, not the open one. A sample saved while another switch finishes first becomes a script of its own without being opened, and Save waits for a switch that is under way.
  - **Announced:** every save is announced to a screen reader, not only the first; opening a saved script or reloading the page announces nothing.
  - **Refused writes:** a refused write no longer hides its real error behind a failed close, the message points to Save As, and it goes away when the script changes.
- `apps/web`: open a file. Open ▸ **Open a file…** (the browser's file picker where it has one, else a file input), or drop a `.fountain` or `.txt` file anywhere on the window, and it opens as a script of its own, clean, with its line breaks and byte-order mark kept for the next save. On Chromium it keeps the file, so Save writes it back in place.
  - A file that is already open (the same file on disk) opens its script instead of a copy.
  - Where saving downloads, a file whose title matches a script in the browser asks first: **Replace that script** (one undoable change), **Open beside it**, or **Cancel**.
  - Files that aren't scripts are refused with a message and nothing changes: over 5 MB, a NUL byte in the first 8 KB, or text that isn't UTF-8 (opening it would replace its characters on the next save).
  - A script with no title page Title is called after its file.
  - **Dropped on the editor:** a file dropped on the script's text opens as its own script and is not also pasted into the one that was open (CodeMirror's own drop handler is turned off for files; text dragged into the editor still drops in as before). A refused file dropped there inserts nothing.
  - **Refusals are announced again:** the same message twice in a row is heard twice (it is cleared, drawn empty, and then set), as is the read-only tab's "Choose “Edit here instead” first" and a failed save.

### Changed

- In a tab that only shows a script open in another tab, Save, Save As, Open a file, and New are turned off, and say to choose "Edit here instead" first. That tab may show old text.
- Revised the design documents to v0.2 after a pre-implementation review:
  - The parser reads two common mistakes leniently: a heading or transition with no blank line after it, and a parenthetical wrapped across lines. Each is flagged for a Strict Fountain lint rule that rewrites the source into spec form.
  - Notes end at the first blank line, per the spec, and an unclosed `[[` stays literal text.
  - Every edit triggers a full reparse; the windowed incremental design is set aside.
  - The parse result gains `doc.trailing`, so printing is lossless for files that end in a newline, plus parse diagnostics for `drafter check`.
  - Templates gain a reserved `omit` role for elements that never print, a physical paper size, exact-name role rules instead of regular expressions, and explicit `extends` merge rules.
  - Pagination rules are now precise: keep-with-next look-ahead, corrected dialogue-split thresholds, engine-added `(CONT'D)` for continued speeches, and no blank pages from forced breaks.
  - Phase 0 tooling is updated: tsdown, Vitest `test.projects`, pnpm 10, `@pdf-lib/fontkit`, `pdfjs-dist`, `@types/node`, and a "Done means" command that works.
  - The kickoff prompt adds rules for changelog entries, commit trailers, and hook setup.
- Saving now works like a desktop app (design, Phase 1): Save and Save As write a `.fountain` file, in place on Chromium and by download elsewhere; leaving with unsaved changes asks first; and an always-on recovery copy in IndexedDB is written as you type, with warnings when the browser blocks it or may clear it. This replaces the earlier policy of never warning.
- Tightened three v0.2 rules found while writing the samples: a character cue is a name plus optional extensions and nothing else, so `MARGARET (60s) sits…` stays action; dual dialogue never takes a continued-speech `(CONT'D)`; and Brave saves by download, because it ships with the File System Access API turned off.

- The README marks Phase 0 done and shows how to install, build, test, benchmark, and run `pnpm drafter` from the repository root. PDFs built from `samples/` and `fixtures/` are ignored by Git.
- The README opens with Drafter's share image.

  - **Phase 2** adds a Beat Board, storylines, writing statistics by day, and screen time per character. Testing with NVDA and VoiceOver moves to Phase 2. Phase 1 checks accessibility with automated tests and doesn't claim WCAG conformance.

### Fixed

- `@drafter/layout` no longer leaves a scene heading or other keep-with-next line alone at the foot of a page when the next block opens with two-space lines. Those lines print blank, but they counted toward the two lines a heading is kept with, so the heading stayed on the page while the block's first words went to the next one. The layout property test found it, rarely (seed `-1435711900`).

### Security

- `@drafter/fountain` now parses hostile input in linear time. Before this fix, a single 4 KB line could stall the parser for seconds through backtracking regular expressions (cue lines, title-page keys, scene numbers), and long paragraphs of unclosed `[[`, deeply nested emphasis, or thousands of note blocks slowed it quadratically. Emphasis nested past 32,767 levels also lost its styling.
- `drafter` (the CLI) prints control characters from scripts, templates, and file names as visible `\u001b`-style escapes, so a hostile file can't send escape sequences to the terminal through a warning or diagnostic, and it won't write a PDF's bytes to a terminal. Fixed-width text output turns C1 control characters into spaces, as it already did C0.
- `@drafter/templates` now validates a template with any number of roles in linear time, and always reports its problems as a `TemplateError`. A template with 200,000 roles took 15 seconds to reject, and one with enough problems overflowed the call stack with a `RangeError` instead.
